# Запись решения (ADR)

Решения razdacha живут в `docs/decisions/NNNN-kebab-case-slug.md`. Формат единый,
отклоняться от него не надо — по нему уже написаны семь записей.

## Перед записью

1. Прочитай `docs/decisions/README.md` — индекс с номерами и статусами.
2. Прочитай существующие ADR по смежной теме. Решение, дублирующее принятое, не заводится.
3. Определи следующий свободный номер: `ls docs/decisions/`.
4. Если новое решение противоречит принятому — не редактируй старое. Заведи новое со
   статусом «принято, заменяет NNNN», а старому поставь «заменено NNNN».

## Формат

```markdown
# NNNN. Краткая формулировка решения

Дата: YYYY-MM-DD · Статус: принято

## Контекст

Что за задача, какие были варианты, какие ограничения. Без «мы решили» — только
обстановка, в которой решение принималось. Если у варианта есть измеримая цена
(байты, миллисекунды, проценты) — приведи числа здесь.

## Решение

Что именно решено. Одним-двумя абзацами, в утвердительной форме.

## Последствия

**Положительные**
- ...

**Отрицательные**
- ...

Отрицательные последствия обязательны. Решение без цены — не решение, а мнение.

## Альтернативы

Что рассматривалось и почему отклонено. По абзацу на вариант.

## Источник в Podkop

Как эта задача решена в Podkop, со ссылками `file:line`, и повторяем мы это или нет.
Если аналога нет — так и написать: «Отсутствует» с объяснением, почему архитектуры
расходятся.
```

## Правила

- **Дату брать реальную**, из окружения, а не выдумывать.
- **Ссылки `file:line` на podkop проверять грепом** перед записью. Строки уже
  разъезжались один раз. Проверять так:
  ```
  grep -n "^имя_функции" ~/Web/podkop/podkop/files/usr/bin/podkop
  ```
- **Числа проверять.** Если приводишь размер файла, количество строк или элементов
  списка — посчитай, не оценивай.
- Секция «Отрицательные последствия» не может быть пустой. Если кажется, что цены нет —
  значит, не найдена.
- Русский язык, тот же тон, что в существующих ADR: без канцелярита и без маркетинга.

## После записи

1. Добавь строку в таблицу `docs/decisions/README.md` (номер, название, дата, статус).
2. Проверь, не противоречит ли решение инвариантам в `CLAUDE.md` — если решение их
   меняет, обнови и `CLAUDE.md`.
3. Найди документы в `docs/`, которые ссылаются на изменённое поведение, и поставь
   ссылку на новое ADR:
   ```
   grep -rn "decisions/" docs/*.md
   ```
4. Не коммить без явной просьбы.
