## TLDR

Эндпоинты данных слоя `api` поверх готового `store`: пиры (со списком, выдачей
клиентского `.conf` и генерацией ключей), туннели (с разбором вставленной строки
через `singbox.Parse`), правила (с переупорядочиванием целиком), настройки и
сводная диагностика. Все маршруты закрыты сессией; ошибки `store` доходят до UI
своими кодами (`404` / `409` / `400`) и русским текстом.

## Goal

Панель без этих эндпоинтов пустая — показывать нечего. Задача не только «отдать
JSON»: половина данных, которые контракт обещает UI (`online`, `rx_bytes`,
`status`, `latency_ms`), приходит из слоёв, которых ещё нет в коде. Слой должен
отдавать их так, чтобы отсутствие источника было видно и не спуталось с нулём, а
клиентский конфиг не выдавался наполовину собранным.

## Domains touched

- [api](../context/api/index.md) — маршруты, DTO, генерация ключей пиров, диагностика
- [store](../context/store/index.md) — только чтение и запись через готовый API слоя

## Decisions

- 2026-07-25 — **публичный ключ сервера живёт в `GET /api/settings`**, полем
  `server_public_key` только на чтение (`PATCH` его игнорирует). Хранимой
  настройкой он не является, но другой сущности API, куда он ложится, нет:
  внутри выдачи конфига его прятать хуже — UI показывает ключ на экране
  настроек, и ради него пришлось бы качать `.conf`. Пока `netstack` не написан,
  поле `null`; источник — необязательный хук `Config.ServerPublicKey`.
- 2026-07-25 — **QR-код рисует клиент**, эндпоинт `/api/peers/{id}/qr` из
  контракта убран. Конфиг — это текст; рабочий кодер уже есть в
  `ui/prototype/app.js` и проверен против `qrencode`. Генератор PNG в демоне
  добавил бы зависимость и второй формат выдачи ради картинки, которая всё равно
  рисуется в браузере.
- 2026-07-25 — **производные поля — указатели и `null`**, а не нули и не
  `"unknown"`-строки. `rx_bytes: 0` означал бы измеренный ноль, `status: "down"` —
  утверждение о туннеле, которого никто не проверял.
- 2026-07-25 — **выдача клиентского конфига отказывает с `503` / `not_ready`**,
  пока неизвестен публичный ключ сервера или `endpoint_host`. Конфиг без них
  выглядит рабочим и не подключается; отказ с перечислением недостающего честнее
  файла с пустой строкой `PublicKey`.
- 2026-07-25 — **ключи пиров генерирует демон** (`crypto/rand` + X25519 через
  `curve25519`, pre-shared всегда), адрес выдаётся первым свободным из пула с
  пропуском адреса сервера, сети и широковещательного. Ключи и адрес из запроса
  не принимаются: иначе два пира легко получают один адрес.
- 2026-07-25 — **тип и `parsed` туннеля не принимаются от клиента**: их даёт
  разбор `raw`, повторяемый при каждой смене строки. Иначе в БД попадает
  «vless» с конфигом socks.
- 2026-07-25 — приватные и pre-shared ключи пиров **не выходят в JSON**: наружу
  они уходят один раз и целиком — в `.conf`. Поэтому у пира отдельный DTO, а не
  `store.Peer` с его тегами.
- 2026-07-25 — `PATCH /api/rules/{id}` накладывает тело на прочитанное правило,
  восстанавливая `id` и `priority`: порядок меняется только через
  `PUT /api/rules/order`, целиком и одной транзакцией.
- 2026-07-25 — в `GET /api/diag` по-настоящему проверяется одно — собирается ли
  конфиг sing-box из текущего снимка БД (чистая функция, ни root, ни сети).
  Остальные шесть проверок остаются в списке со статусом `unknown` и объяснением
  в `detail`: пропавшая строка читалась бы как «всё в порядке». В `overall`
  `unknown` хуже `ok`, но лучше `warn`.
- 2026-07-25 — `list_update_interval` в API — секунды, а не наносекунды
  `time.Duration`: представление Go не должно протекать в контракт.

## Не сделано здесь

`POST /api/tunnels/{id}/check`, `GET /api/lists/community`, `/api/apply`,
`/api/logs`, `/api/ws` — отдельные задачи; до тех пор общий обработчик под
`/api/` отдаёт им `401` без сессии и `404` с ней. Живые данные пиров и туннелей
подключаются вместе с `netstack` и клиентом Clash API — места под них уже
размечены (`peerResponse`, `tunnelResponse`, хук `ServerPublicKey`).

## Acceptance criteria

- [x] каждый новый маршрут закрыт сессией; без неё `401` с кодом `unauthorized`
- [x] `ErrNotFound` → `404`, `ErrInUse` → `409`, `ErrInvalid` → `400`, текст на русском
- [x] удаление туннеля со ссылающимся правилом даёт `409` и называет правило
- [x] клиентский конфиг содержит `DNS`, `MTU`, `AllowedIPs`, `PersistentKeepalive`,
      `PresharedKey` по `docs/03-networking.md`
- [x] производные поля отсутствуют (`null`), а не равны нулю
- [x] переупорядочивание правил меняет порядок целиком, частичный список отклоняется
- [x] разбор корректной и битой строки туннеля покрыт тестами
- [x] тесты на `httptest` с временной БД, без сети и root; `go vet`, `go test`,
      `gofmt`, `golangci-lint` чисты
