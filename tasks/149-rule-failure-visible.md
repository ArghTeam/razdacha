# 149 — отказ правила виден в интерфейсе

Issue: [#149](https://github.com/ArghTeam/razdacha/issues/149) · слои: api, ui

## Цель

[ADR 0013](../docs/decisions/0013-unavailable-tunnel-rejects.md) сменил режим отказа с
«правило молча течёт» на «правило молча не работает». Вторая половина принципа «отказ
виден, утечка не видна» не сделана: в панели правило с выключенным туннелем, с пулом без
живых серверов или с непрогрузившимся списком выглядит ровно как рабочее.

Разбор соседей — `docs/research/singbox-panels-2026-07.md` (issue #147): FlClash и Karing
красят мёртвую цель прямо в списке правил, Karing единственный показывает состояние
источников списков, 3x-ui дёргает у живого ядра пробник маршрута. Прецедента у самого
`reject`-правила нет ни у кого (см. `context/singbox/invariants.md`) — тем важнее, чтобы
наш отказ был читаем.

## Три части

1. **Мёртвая цель.** Строка правила отличает недоступный туннель от рабочего. Данные уже
   на руках: `enabled`, `status`, `pool` приходят в `GET /api/tunnels`. Новых полей API
   не нужно.
2. **Статус списков.** Рядом с чипом списка — состояние источника: обновился, не
   обновился с текстом ошибки, ни разу не обновлялся (три разных состояния, не два).
   Метаданные лежат в `internal/lists`, наружу не отдаются — потребуется расширить ответ
   API правил, но не отдельным запросом на каждый список.
3. **Пробник маршрута.** Поле «домен» и кнопка: какое правило и какой outbound победят по
   ответу живого sing-box через `internal/clash`. Прямо со страницы правил, без ухода на
   другой экран.

## Границы

- Порядок «копится — применяется кнопкой» не трогается: пробник спрашивает то ядро, что
  работает сейчас, и это надо честно показать, если конфиг разошёлся с БД.
- Недоступный Clash API даёт понятную ошибку, а не пустой результат — консистентно с
  инвариантом «недоступный Clash оставляет поля `null`» (`context/api/invariants.md`).
- Пустота не заполняется выдумкой (`context/ui/invariants.md`): «неизвестно» — это текст,
  а не ноль и не зелёная галочка.

## Критерии приёмки

Полный список — в issue. Коротко: правило с мёртвым туннелем видно без наведения и клика;
рабочее правило вида не меняет; три состояния списка различимы; пробник отвечает по живому
ядру и внятно сообщает, когда ядро недоступно.

## Decisions

- 2026-08-15: три части ведутся одной веткой и одним PR — они об одном и том же экране и
  разъезжаются в конфликтах, если резать на три.
- 2026-08-15: **пробник спрашивает ядро двумя вопросами, а не одним.** Аналога
  `routeTest` из 3x-ui у Clash API sing-box нет: есть `GET /rules` (правила в порядке
  проверки и действие каждого) и `GET /dns/query` (ответ того же резолвера, к которому
  ходят клиенты). Первый даёт порядок и outbound, второй — поймало ли домен хоть одно
  правило: FakeIP выдаётся только совпавшему (docs/04-dns-fakeip.md).
- 2026-08-15: **состава наборов ядро не отдаёт, и выдумывать его нельзя.** Содержимое
  `.srs` community-списков живёт внутри sing-box. Правило, чьи условия демону видны
  целиком (свои домены, plain-список из кэша), называется победителем; правило со
  списком — кандидатом (`certain: false`), и `rule` остаётся `null`. Единственный
  кандидат при выданном FakeIP становится победителем: поймать домен было больше некому.
- 2026-08-15: **состояний списка пять, а не три.** К трём из issue добавились `core`
  (домены ведёт сам sing-box, у демона состояния нет) и `unknown` (планировщик не
  поднялся). Оба — честная пустота: выдавать их за успешное обновление нельзя.
- 2026-08-15: отказ источника при живом кэше — отдельное положение внутри `failed`:
  `error` есть, `updated_at` — время прошлого успеха. Раньше `Fetcher.Parse` эту
  ошибку глотал, и наружу она не выходила вовсе.
- 2026-08-15: такт опроса панели молчит, пока курсор стоит в `input`/`textarea` на
  экране. Перерисовка заменяет разметку целиком, и поле пробника теряло бы набранное
  вместе с фокусом каждые пятнадцать секунд.
