## TLDR
Пул бесплатных VLESS — встроенная сущность в единственном экземпляре: появляется сам,
не создаётся, не правится, не удаляется. Своё меню и своя модалка «Детали» со списком
серверов. Первая версия сделала пул ещё и создаваемым руками — это отменено.

## Goal
Пулом бесплатных ключей можно пользоваться и видеть его состав, и он в системе один.

## Domains touched
- [store](../context/store/) — признак встроенной записи, признание существующего пула
  встроенным вместо заведения второго
- [api](../context/api/) — запрет создания пула, ручка списка серверов, отказ на удаление,
  обновление каталога без ожидания расписания
- [lists](../context/lists/) — обновление по требованию не зависит от кэша расписания
- [ui](../context/ui/) — два набора меню вместо трёх, модалка «Детали», честная подпись
  числа серверов

## Decisions
- 2026-07-26 — Признак встроенности — колонка `builtin` (миграция 4), а не совпадение
  каталога с `lists.DefaultPoolCatalogURL`: адрес по умолчанию может поменяться в релизе,
  и настоящая встроенная запись «перестала бы» быть встроенной. `UpdateTunnel` колонку не
  пишет — иначе запрет на удаление обходился бы через `PATCH`.
- 2026-07-26 — Пул заводится **выключенным**: свежая установка не должна сама начинать
  ходить на чужой сайт за ключами.
- 2026-07-26 — **Пул только один и только встроенный** (уточнение пользователя). Отсюда:
  `POST /api/tunnels` со ссылкой на каталог отвечает отказом; вариант меню «пул, заведённый
  руками» убирается; существующий пул при обновлении признаётся встроенным, а не
  дублируется вторым. Развилка «имя занято» и запасное имя «(встроенный)» становятся
  ненужными и убираются.
- 2026-07-26 — Разбор ссылки на каталог в `singbox.Parse` (#66) остаётся: им пользуется
  заведение встроенного пула. Отказ в `POST /api/tunnels` стоит **после** разбора, чтобы
  битая ссылка получала своё объяснение, а не общий отказ.
- 2026-07-26 — Меню собирается по признаку «это пул», а не по флагу `builtin`: пул без
  флага бывает только следом ручной правки БД, и «Изменить» с «Удалить» у него означали
  бы, что пулов заводят несколько. `DELETE` такого пула API по-прежнему разрешает —
  иначе лишний пул было бы нечем убрать.
- 2026-07-26 — Обход по требованию получает пул целиком (`RefreshPool(ctx, PoolTunnel)`)
  вместо поиска по идентификатору в наборе расписания. `ErrPoolNotFound` вместе с
  поиском исчез: отказывать стало не на чем (#74).
- 2026-07-26 — Имя встроенного пула занято туннелем пользователя — пул не заводится, а
  ошибка уходит в лог. Запасное имя убрано вместе с развилкой; случай остался только для
  не-пула с тем же именем, а переименовать свой туннель пользователь может сам.
- 2026-07-26 — Отказ на удаление отдан через существующий `store.ErrInUse` → 409. Новый
  сентинел потянул бы правку `storeError` ради одного случая.
- 2026-07-26 — У серверов вне ротации `alive` и `latency_ms` строго `null`: их никто не
  проверял, а `false` был бы утверждением о непроверенном сервере. Ссылки `vless://`
  наружу не отдаются — в них UUID.
- 2026-07-26 — Число серверов подписывается честно. После #72 список в БД копит известные
  серверы и выкидывает только после трёх пропусков подряд, поэтому он больше того, что
  каталог отдаёт за раз (наблюдалось 137 в БД против 125–128 в каталоге). Подпись
  «серверов в каталоге» неверна.

## Notes
- Проверено на стенде на первой версии: заведение выключенным, идемпотентность (три
  перезапуска — тот же `id`), миграция 3 → 4 без потери туннелей, пира, правила и настроек,
  409 на удаление встроенного, `PATCH enabled` работает, ручка отдаёт 16 в ротации и 113
  с `null`, `vless://` в теле — ноль вхождений, модалка без горизонтального скролла в
  1000px и 390px. Это всё сохранить.
- На стенде пул уже помечен встроенным и называется «Бесплатные VLESS (встроенный)» —
  существующее имя не переименовывать, менять только логику заведения.
- Заодно чинится #74: обновление каталога по требованию на свежем пуле отвечает 404,
  потому что `PoolManager` узнаёт о пуле раз в 30 секунд, а `ErrPoolNotFound` замапплен
  в «Туннель не найден». Модалка опирается на эту кнопку.
- Не входит: #75 (`/api/ws` не реализован, а документы его обещают) — отдельная задача.

## Acceptance criteria
- [x] `POST /api/tunnels` со ссылкой на каталог отвечает отказом, а не создаёт второй пул
      — 409 «Пул бесплатных ключей уже есть…», `TestCreatePoolFromCatalogURLIsRejected`
- [x] В меню пула нет «Изменить» и «Удалить» ни при каком раскладе; у обычного туннеля
      меню не изменилось — проверено на моке в обеих ширинах
- [x] На установке, где пул уже есть, после обновления пул один и помечен встроенным;
      второй не заводится — `TestEnsureBuiltinPoolAdoptsExisting`,
      `TestEnsureBuiltinPoolPicksOneOfMany`; повтор на стенде — за человеком
- [x] Заведение идемпотентно, пул выключен, миграция не теряет существующие данные
      — миграция 3 → 4 проверена на стенде на первой версии, схема с тех пор не менялась
- [x] `DELETE` встроенного — 409, и запрет не обходится через `PATCH`
- [x] Ручка деталей: в ротации ровно `poolMaxServers`, у остальных `alive` и `latency_ms`
      равны `null`, `vless://` в теле отсутствует
- [x] Обновление каталога работает сразу после появления пула, без ожидания тика (#74)
      — `TestRefreshPoolWithoutSetTunnels`, `TestRefreshPoolBeforeScheduleKnowsIt`
- [x] Число серверов подписано честно — «известно N серверов» на карточке и в модалке
- [x] Модалка проверена на моке в двух ширинах: без горизонтального скролла и ошибок консоли
      — 1000×900 и 390×844, `documentElement.scrollWidth` равен ширине окна, консоль пуста

Осталось за живым стендом: обновление установки, где пул уже заведён руками (пул должен
стать один и помеченный встроенным), и кнопка «Обновить каталог» сразу после появления пула.
