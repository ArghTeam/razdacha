# 187 — пул терпит битый ключ, а не роняет весь конфиг

Issue: #187. Заводится новое ADR.

## Проблема

Общий пул (#181) наполняется бесплатными ключами чужой подписки igareck. Ключ,
прошедший наш парсер, но не прошедший `sing-box check` (незнакомый sing-box случай),
валит проверку **всего** конфига. По инварианту «конфиг генерируется целиком, при
ошибке остаётся прежний» это роняет **весь** пул — панель показывает 0 живых.

Точечно этот класс латали дважды: `flow=xtls-rprx-vision-udp443` (#176) и `reality`
без uTLS (#183). Парсер не предвидит все правила sing-box — нужна устойчивость на
сборке пула.

## Контекст (проверить preflight'ом)

- `internal/singbox/pool.go` — `poolMaxServers = 16`; `selectPoolServers` берёт первые
  16 уникальных серверов пула в конфиг; `PoolMembers` — тег члена → сервер.
- `internal/singbox/apply.go` / `apply_exec.go` — `BinaryChecker.Check` = `sing-box
  check -c <файл>`; поток «генерация → check → применить, при ошибке `ErrCheckFailed`,
  прежний конфиг остаётся».
- Ошибка от рантайма имеет вид `initialize outbound[N]: <причина>` (у wireguard-члена
  может быть `endpoint[N]`). Пример вживую: `outbound[7]: uTLS is required by reality
  client`.

## Подходы (выбрать в ADR, обосновать)

**A. Drop-by-error-index на применении (рекомендую).** Генерируем конфиг целиком как
сейчас → `check`. Если провалился и виноватый `outbound[N]`/`endpoint[N]` — **член
пула**, выкидываем именно его, регенерируем, повторяем (с потолком повторов). Если
виноват ручной туннель или что-то вне пула — отказ как сейчас (прежний конфиг). Плюсы:
общий случай (битых нет) — один `check`, как сегодня; цена платится только когда ключ
битый; без изменения схемы. Минус: разбор индекса из текста ошибки и карта
`индекс → член пула` (генератор знает порядок outbounds/endpoints).

**B. Повалидировать членов по одному при обновлении пула.** На обходе каталога (раз в
~12ч) каждый кандидат проверяется отдельным `sing-box check`, в БД идут только годные;
config-gen берёт заведомо годных. Плюс: config-gen всегда проходит. Минусы: N проверок
на обход; чтобы не гонять на каждой генерации — кэшировать годность в составе пула
(правка store/lists-структуры).

Выбор — за ADR. Если A: карту `индекс → источник` вынести из генератора явно, чтобы
выкидывать точно; повтор ограничить (напр. ≤ числа членов пула); дренаж добора —
годными из остатка до `poolMaxServers`.

## Обязательно

- **Терпимость только к членам пула.** Ручной туннель (`source != pool`), не прошедший
  check, по-прежнему валит применение целиком — это ошибка пользователя, её нельзя
  глотать. Проверить, что drop не затрагивает не-pool outbounds.
- **Виден в логе, ключ не утекает** (ADR 0124/#124): лог исключения — `хост:порт` +
  причина, без полной ссылки с ключом.
- **Добор до потолка** годными из остатка, чтобы пул не оставался полупустым.
- **Инвариант «конфиг целиком + check» сохраняется**: конфиг по-прежнему генерируется
  и проверяется целиком; меняется лишь то, что негодный член пула выкидывается и
  конфиг пересобирается, а не остаётся прежним. Явно связать с ADR 0013 (недоступный
  туннель → reject) — это про доступность, а не про негодность членов; здесь другое.
- **ADR** по формату `docs/decisions/`, обновить README индекс.
- **Документация ведёт код.** Логи слоёв singbox (+lists, если тронут состав пула).
  Записи ≤400 байт (кириллица вдвое, хук OKP004).
- `make build`/`make test`, `go run mvdan.cc/gofumpt@latest -w` по изменённым `.go`,
  `sqlclosecheck` (defer rows.Close). CI гоняет gofumpt/sqlclosecheck.
- Ребейз запрещён; PR наружу, мержит оркестратор.

## Критерии приёмки

См. issue #187. Тест на пул с битым членом; битый ручной туннель по-прежнему отказ;
исключение логируется без ключа; ADR; проверено на стенде (пул применяется при битом
ключе в каталоге, живых не 0).
