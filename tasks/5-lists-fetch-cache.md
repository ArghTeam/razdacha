## TLDR

Слой `internal/lists`: загрузка `.srs` и plain-списков по URL с условными запросами
(`ETag`/`Last-Modified`), кэш в каталоге состояния с атомарной подменой файла и
расписание обновления по `list_update_interval`. Подсети отдаются отдельным
срезом — их дублируют в nft-сет, потому что FakeIP их не закрывает. Тесты идут
на `httptest.Server`, реальной сети нет.

## Goal

Демон должен сам держать актуальными списки, из которых ему нужны подсети, и
переживать недоступность источников: устаревший список лучше пустого.

## Decisions

- 2026-07-25 — тело списка читается в память целиком (потолок 16 МиБ), проверяется
  и только потом пишется во временный файл рядом и переименовывается. Rename в
  пределах каталога атомарен, поэтому оборванная загрузка не оставляет обрезанного
  списка на месте валидного. Потолок обязателен: без него «список» на сотни
  мегабайт выест память демона.
- 2026-07-25 — целостность тела проверяется сверкой с `Content-Length`, а не только
  ошибкой чтения: `net/http` отдаёт `ErrUnexpectedEOF` не на всех видах обрыва, а
  недосчитанный список молча выкинул бы половину подсетей.
- 2026-07-25 — метаданные (`ETag`, `Last-Modified`, время, размер) лежат отдельным
  файлом `<hash>.meta.json` рядом с телом `<hash>.body`; имя — хэш адреса, потому
  что URL содержит символы, недопустимые в имени файла. Метаданные без тела
  считаются отсутствующими: иначе на 304 отдавать было бы нечего.
- 2026-07-25 — расписание живёт в `Manager`: `Start` возвращается сразу, первый
  прогон идёт в горутине. Неудачный прогон повторяется через `Retry` (минута,
  удвоение до 15 минут), а не через суточный интервал: на свежем VPS сеть
  поднимается позже демона. Podkop решает то же самое циклом проверок доступности
  GitHub (`podkop/files/usr/bin/podkop:487-533`).
- 2026-07-25 — `Manager.Updates()` — буферизованный на одно значение канал с
  неблокирующей отправкой: слой netstack перезаливает по нему nft-сет, и медленный
  подписчик расписание не тормозит.
- 2026-07-25 — `.srs` разбирается своим кодом (`srs.Read` с `recover = true`), а не
  внешним `sing-box rule-set decompile`, как у Podkop: пакет `common/srs` тянет уже
  имеющиеся зависимости, новых модулей в `go.mod` не появилось. Без `recover` Read
  оставляет скомпилированные матчеры и не заполняет `ip_cidr`.
- 2026-07-25 — из подсетей берётся только IPv4: nft-сет объявлен `ipv4_addr`, а IPv6
  у клиентов выключен (ADR 0005). Отброшенные строки считаются в `List.Skipped`,
  разбор из-за них не падает — источник чужой, и терять тысячи строк из-за одной
  битой нельзя.
- 2026-07-25 — `Sources` берёт из community-списков только те сервисы, у которых в
  allow-domains есть `Subnets/IPv4/<key>.lst` (каталог ключей — в слое lists, как и
  обещал комментарий генератора). Свои `remote_lists` качаются в любом виде,
  включая `.srs` и `.json`: маршрутизацию по ним ведёт sing-box, но подсети всё
  равно нужны в nft-сете. Правила с `action = block` тоже дают подсети — чтобы
  sing-box отбросил трафик, тот сперва должен дойти до него по метке nft.
- 2026-07-25 — при недоступном источнике `Fetcher.Parse` берёт прошлую версию из
  кэша и лишь логирует предупреждение; ошибка возвращается, только когда кэша нет.

## Acceptance criteria

- [x] сеть в тестах замокана, реальных запросов нет — только `httptest.Server`
- [x] битый, пустой, оборванный и 5xx-ответ не затирают валидный кэш
- [x] `304` не трогает тело, обновляется только время проверки
- [x] подсети отдаются отдельным срезом (`Manager.Subnets`), отсортированным и без
      повторов — готовые элементы nft-сета
- [x] расписание не блокирует старт демона: `Start` возвращается сразу
- [x] повторный прогон идемпотентен: кэш и набор подсетей те же
