## TLDR
Пул из #62 показывается в списке туннелей как обычный айтем, но выделенный и со своими
данными: каталог, сколько серверов живо, какой выбран, время обновления, кнопка обновить.
UI пишется сразу под зафиксированную форму ответа, REST-часть — после ядра.

## Goal
Пулом можно управлять и видеть его состояние из панели, не выходя из экрана «Туннели».

## Domains touched
- [api](../context/api/) — блок `pool` в ответе списка туннелей, ручка обновления,
  чтение живых серверов из `internal/clash`
- [ui](../context/ui/) — карточка пула на экране «Туннели», её выделение и кнопка

## Decisions
- 2026-07-26 — Пул это тот же `.row` на экране «Туннели», не отдельный экран и не отдельная
  сущность в интерфейсе. Правило навешивается на него штатно, как на любой туннель.
- 2026-07-26 — Форма ответа `GET /api/tunnels` для пула зафиксирована до начала работы
  (см. issue): `pool: {catalog_url, servers_total, servers_alive, current: {name, country,
  latency_ms}, updated_at, next_update_at}`. UI пишется под неё, ручка обязана её отдать.
- 2026-07-26 — Живой сервер и число живых читаются из Clash API через существующий
  `internal/clash` (он же в диагностике): это чтение того, что `urltest` уже насчитал,
  а не вторая собственная проверялка.
- 2026-07-26 — Работа делится на две части по зависимости от #62: `ui/dist` — статика без
  сборщика, к Go не компилируется, поэтому пишется параллельно ядру. `internal/api` читает
  поля пула из БД, которых до #62 нет, поэтому идёт после.
- 2026-07-26 — Тип туннеля в интерфейсе руками не выбирается (см. шапку `tunnels.js`):
  для пула вставляется URL каталога, распознавание остаётся на сервере в
  `POST /api/tunnels/parse`.

## Notes
- Карточка туннеля — `ui/dist/js/screens/tunnels.js:47`: точка статуса, бейдж типа, бейдж
  задержки, строка меты, кнопка «Проверить» и меню. Пул встраивается в неё.
- Метка типа живёт в `TUNNEL_LABEL` (`ui/dist/js/util.js`), адрес карточки — `tunnelEndpoint`.
- Кнопка обновления — `POST /api/tunnels/{id}/refresh`.
- Выключенный пул не должен показывать статистику живых серверов: цифры от выключенного
  туннеля — ложь, а не ноль.
- Ядро пула: #62, ветка `roman/62-vless-pool-rotation`.

## Acceptance criteria
- [ ] Пул виден в списке туннелей как обычный айтем, но отличим на глаз; правило
      навешивается на него штатно
- [ ] На карточке видно каталог, число серверов и живых, текущий сервер, время обновления
- [ ] Кнопка обновления вызывает `POST /api/tunnels/{id}/refresh` и показывает результат
- [ ] Выключенный пул выглядит как выключенный туннель, без ложной статистики
- [ ] UI проверяем на замоканном ответе, до готовности ручки
