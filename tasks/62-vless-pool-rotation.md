## TLDR
Туннель нового вида — пул: URL каталога вместо одного конфига, N vless-outbound'ов и
`urltest` под тегом туннеля. Health-check и переключение отдаются sing-box, поэтому смена
сервера не трогает ни конфиг, ни правила, ни остальные туннели.

## Goal
Один туннель, который сам держится за живой бесплатный VLESS-сервер и не роняет соседей.

## Domains touched
- [store](../context/store/) — пул как форма туннеля: URL каталога, список разобранных
  серверов, время обновления; миграция схемы
- [singbox](../context/singbox/) — генерация N outbound'ов + `urltest` с тегом туннеля,
  детерминированный порядок серверов
- [lists](../context/lists/) — разборщик страницы каталога и расписание обновления пула
  рядом с существующими `Fetcher`/`Manager`
- [api](../context/api/) — CRUD пула, его состояние и выключение
- [ui](../context/ui/) — экран туннелей: пул, время обновления, живые серверы

## Decisions
- 2026-07-26 — Ротация через `urltest` sing-box, не подмена конфига по таймеру: health-check
  внутри sing-box, смена сервера без перезапуска. Первый шаг работы — ADR 0010, уточняющий
  0003 («туннель — ровно один outbound либо endpoint»), до кода.
- 2026-07-26 — Серверы пула сериализуются в стабильном порядке (сортировка по URL).
  Причина: `apply_exec.go:60` перезагружает через `systemctl reload-or-restart`, то есть
  перезапускает sing-box и роняет все туннели; единственная защита — `apply.go:202`
  `sameOnDisk`, а она срабатывает только на байт-в-байт одинаковом конфиге.
- 2026-07-26 — Два интервала разведены по цене: ротация бесплатна (`urltest`), обновление
  списка дорого (перезапуск). Обновление редкое и только при изменившемся наборе.
  Гипотеза для проверки: `urltest.interval` 3 минуты, обновление 12 часов — сайт объявляет
  `profile-update-interval: 12`. Итоговые значения обосновать здесь же.
- 2026-07-26 — Источник: HTML-разбор `vpnkeys.me/protocol/vless`. Общий загрузчик
  base64-подписок выведен из объёма — их `/sub` отдаёт 500 на любой UA; код формировать так,
  чтобы загрузчик добавился позже без переделки.
- 2026-07-26 — `internal/singbox/parse_url.go` не правится: 127/127 живых ключей
  разбираются как есть. Корпус кладётся в `internal/singbox/testdata`.
- 2026-07-26 — Полнота пула не требуется: хватает нескольких работающих ключей, поэтому
  потолок числа серверов в конфиге допустим и желателен (отбор по пингу карточки).
- 2026-07-26 — **Интервалы выбраны как в гипотезе: `urltest.interval` 3 минуты, обход
  каталога 12 часов** (`singbox.PoolTestInterval`, `lists.DefaultPoolInterval`).
  Три минуты: ротация внутри группы бесплатна — пробы идут внутри процесса, конфиг на диске
  не меняется, соседние туннели не задеты; мёртвый сервер держится в работе не дольше одного
  интервала, а 16 проб раз в три минуты — это меньше одного запроса в секунду. Меньше трёх
  минут смысла нет: `urltest` всё равно переключается по ошибке соединения, не дожидаясь
  пробы. Двенадцать часов: обход дорог — изменившийся набор перезаписывает конфиг, а это
  перезапуск sing-box; сайт сам объявляет `profile-update-interval: 12`, то есть чаще
  ходить не за чем. Рядом заданы `tolerance` 50 мс (без запаса группа скакала бы на шуме
  измерений) и `idle_timeout` 30 минут — дефолт sing-box, задан явно, потому что интервал
  проверки обязан быть меньше него.
- 2026-07-26 — **Потолок серверов в конфиге — 16** (`singbox.poolMaxServers`). Отбор идёт
  по пингу карточки, при равенстве — по URL. Шестнадцать переживают отказ большинства
  участников (из 127 живых на любой момент работает часть), дают 16 проб на интервал вместо
  127 и оставляют конфиг читаемым руками. Полнота не нужна: правило всё равно уходит в
  одного лучшего.
- 2026-07-26 — **Пул без пригодных серверов пропускается, а не роняет генерацию.** Он
  выпадает из конфига вместе со ссылающимися на него правилами — как выключенный туннель —
  с записью в лог (`slog.Warn`). Ошибка означала бы, что недоступный чужой каталог или пустой
  пул сразу после создания замораживает весь конфиг, включая исправные туннели; выбор в пользу
  «работает остальное». Правило на такой пул пришлось бы пропускать в любом случае: иначе оно
  ссылается на несуществующий тег и `sing-box check` отвергает конфиг целиком.
- 2026-07-26 — **Изменением состава считается только набор ссылок.** Пинг, страна и подпись
  карточки в сравнении не участвуют: пинг пляшет на каждом обходе, и если считать его
  изменением, каждое обновление каталога переписывало бы конфиг и перезапускало sing-box.
  Пинги обновляются вместе с составом — там, где перезапуск всё равно происходит.
- 2026-07-26 — Неактивные карточки (`key-status status-active` отсутствует) в пул не идут:
  сайт сам помечает мёртвые ключи, и место в конфиге с пробами `urltest` на них тратить
  незачем.

## Notes
- Разборщик готов и проверен, лежит в скратчпаде сессии:
  `scratchpad/vpnkeys/main.go` (stdlib, `go vet` чистый) — писался под перенос в
  `internal/lists`. Рядом `keys.txt` и `keys.json` — корпус для testdata.
- Конец обхода страниц определять числом карточек, не числом ключей: карточек без
  `data-key-url` на первой странице от 1 до 4.
- `per_page` принимает только 20/50/100; 500 молча схлопывается в 50.
- Живость ключей не проверена. Проверять только на стенде Debian: сетевые пробы и установка
  прокси-клиентов на машине разработчика запрещены.
- Разметка каталога — server-side Blade, привязка к классам `key-card`/`copy-key-btn`.
  Её правка ломает разбор молча → тест на сохранённой фикстуре страницы обязателен.
- Инвариант «конфиг генерируется целиком из состояния БД» сохраняется: пул живёт в БД,
  генератор по-прежнему не патчит конфиг частично.

## Acceptance criteria
- [x] Туннель-пул создаётся по URL каталога, правило ссылается на него как на обычный туннель
      (`store`: `SourcePool`, миграция 3; `TestPoolBuildsGroupUnderTunnelTag`). CRUD в API —
      второй заход
- [x] Обновление при неизменившемся наборе серверов не даёт перезапуска
      (`ApplyResult.Reloaded == false`) — `TestPoolApplyWithoutReload`,
      `TestPoolManagerIgnoresPingDrift`
- [ ] Мёртвый сервер выводится из работы без перезапуска демона; на стенде проверено, что
      трафик через другой туннель при смене сервера не рвётся — **только на стенде**
- [x] Выключенный пул не попадает в конфиг и не обновляет список (`TestPoolDisabled`,
      `TestPoolManagerSkipsDisabled`)
- [x] Разбор фикстуры страницы даёт весь пул; карточки без ссылки считаются и не отменяют
      загрузку (`TestPoolCatalogServers`, `TestPoolCatalogPageEndsByCards`)
- [x] Оба интервала выбраны, обоснованы в этой спеке и заданы в коде значениями по умолчанию
- [x] `docs/decisions/0010-tunnel-pool-urltest.md` заведён, 0003 помечен как уточнённый

Не сделано намеренно (второй заход): слои `api` и `ui` — REST для пула и экран туннелей.
Расписание `lists.PoolManager` в `cmd/razdachad` пока не включено: пулов в БД без API не
появится, а лишняя горутина без источника данных только шумела бы в логах.
