## TLDR
Правило может указать цепь туннелей («VLESS → WARP») второй выпадашкой в модалке.
Цепь материализуется отдельным outbound с `detour`, одинаковые цепи схлопываются.
Экран туннелей не меняется. Требует ADR.

## Goal
Дать правилу выход «ВПН + WARP», не заводя дублей туннелей в инвентаре.

## Domains touched
- [store](../context/store/) — хвост цепи у правила, миграция
- [singbox](../context/singbox/) — теги цепей, `detour`, дедупликация
- [api](../context/api/) — валидация цепи
- [ui](../context/ui/) — вторая выпадашка в модалке правила

## Decisions
- 2026-07-27 — цепь вешается на правило, а не на туннель: иначе «просто WARP» и
  «VLESS → WARP» требуют двух записей WARP в инвентаре, и из правила не видно,
  сколько за именем прыжков.
- 2026-07-27 — `detour` у sing-box принадлежит outbound, поэтому цепь не выражается
  одним route-правилом: на каждую различную цепь генерируется свой outbound с тегом,
  дедупликация по составу цепи.
- 2026-07-27 — валидация сводится к запрету повтора туннеля внутри цепи; цикл при
  явном списке звеньев невозможен.
- 2026-07-27 — ADR отдельным PR до кода: решение должно читаться без диффа реализации.
- 2026-07-27 — закрыто [ADR 0012](../docs/decisions/0012-tunnel-chain-detour.md): пул
  допустим только первым звеном. У группы `urltest` нет `DialerOptions`, то есть носителем
  `detour` она быть не может, а клон группы под цепь ломает «один туннель — один тег» из
  0010 и снятие состояния из 0011. Целью `detour` тег пула быть вправе: он резолвится в сам
  объект группы, а участника группа выбирает на каждом дозвоне — ротация цепь переживает.

## Acceptance criteria
- [ ] в правиле указывается цепь из двух и более туннелей, в конфиге появляется `detour`
- [ ] две одинаковые цепи в разных правилах дают один outbound
- [ ] повтор туннеля внутри цепи отклоняется на русском до `sing-box check`
- [ ] на стенде: список A выходит с адреса Cloudflare через наш VLESS, список B — с адреса VLESS
- [ ] ADR принят, на него ссылается инвариант слоя singbox
