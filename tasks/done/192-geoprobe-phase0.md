# 192 (Фаза 0) — проба геоблока по запросу

## Цель
Оператор с экрана правил проверяет, не отдаёт ли домен геоблок (403/451/Cloudflare-1020)
**напрямую с адреса сервера**. Только прямая проба, по кнопке. Никакого туннеля, фонового
скана, watchlist, телеграма и http-inbound — это Фаза 1 (отдельная задача).

## Почему так (из разведки и двух ревью, см. issue #192)
- Clash-delay читать статус не умеет (шлёт HEAD, код игнорит) — но Фазе 0 он и не нужен.
- Демон ходит обычным `net/http` со **своего** адреса: его резолв идёт мимо FakeIP-резолвера
  sing-box (тот только для клиентов wg0 на 10.8.0.1), поэтому реальный IP берётся сам собой.
  **Не использовать** Clash `/dns/query` / `ResolveA` — она отдаёт FakeIP для доменов под правилом.
- Вердикт формулировать честно: «напрямую отдаёт 403 — похоже на геоблок», без утверждений,
  что туннель это чинит (через-туннельное подтверждение — Фаза 1).

## Backend
- Новый хендлер рядом с `handleRouteTest` (`internal/api/routeprobe.go`), напр.
  `POST /api/domain/reachability` (или `/api/geoprobe`), зарегистрировать в
  `internal/api/handlers.go` через `s.protect` (авторизованный, как route/test).
- Вход: `{ "domain": "chatgpt.com" }`. Нормализовать домен так же, как route-probe
  (переиспользовать нормализацию из routeprobe.go, не дублировать).
- Проба: `http.Client` со своим таймаутом (~8–10 с), запрос `GET https://<domain>/`
  (или HEAD, но для Cloudflare-1020 нужно тело/заголовки — тогда GET с ограничением чтения тела).
  UA — вменяемый (не пустой). Редиректы не гнать бесконечно (ограничить 2–3).
- Классификация статуса:
  - `2xx/3xx` → `reachable` — «напрямую открывается».
  - `403`, `451` → `geoblock_suspect` — «напрямую отдаёт NNN — похоже на геоблок».
  - Cloudflare error **1020** (обычно HTTP 403 + тело `error code: 1020` / заголовок `cf-*`)
    → `geoblock_suspect` c уточнением «Cloudflare 1020».
  - Соединение оборвалось/таймаут/TLS-ошибка → `unreachable` — «напрямую не отвечает
    (блокировка провайдера или сайт недоступен) — по коду не различить».
- Ответ: `{ "domain", "status": <int|0>, "class": "...", "verdict": "<русский текст>" }`.
  Текст ошибок и вердикт — на русском, показываются как есть.
- Ошибки оборачивать `fmt.Errorf("...: %w", err)`; логи — `log/slog`.

## Frontend
- На экране правил (`ui/dist/js/screens/rules.js`) рядом с существующим пробником
  «Куда уйдёт домен» (`probeView`, `POST /api/route/test`) — соседняя проба
  «Проверить доступность напрямую»: то же поле ввода домена или отдельная кнопка,
  показывает вердикт как есть. Стиль в тон существующему `probe-verdict`.
- Клиент API — добавить метод в `ui/dist/js/api.js` (по образцу route/test).
- UI не собирается — правим готовую статику в `ui/dist`.

## Инварианты
- Ноль изменений в генераторе sing-box и его конфиге. Никаких inbound'ов.
- Проба идёт с сервера (демона), не с машины оператора («не проверять локально»).
- `CGO_ENABLED=0`, только stdlib `net/http` — новых зависимостей не тащить.

## Тесты
- Юнит на классификатор статуса: 200→reachable, 403→geoblock_suspect,
  451→geoblock_suspect, тело с `error code: 1020`→geoblock_suspect(CF), таймаут/ошибка→unreachable.
- Хендлер: пустой/битый домен → 400; нормализация домена. Сети в тесте не касаться
  (класс-функцию тестировать отдельно от реального похода наружу; сам поход — за интерфейсом/подменой).

## Критерии приёмки
- `make build`, `make test` зелёные; CI (gofumpt/sqlclosecheck) зелёный до мержа.
- На стенде 186.246.29.11: проба `chatgpt.com`/`claude.ai` → «похоже на геоблок» (403),
  `example.com` → «открывается». Проверяет оркестратор после мержа. **Только стенд.**
