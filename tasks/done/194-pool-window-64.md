# 194 — окно urltest пула с 16 до 64

## Цель
Единый пул использует не 16, а 64 сервера в urltest-группе. urltest уже перепроверяет
каждые 3 мин и переключается на живого без reload — нужно лишь дать ему больше кандидатов,
чтобы живой резерв был, а не 2 живых из 16.

## Данные стенда (обоснование)
81 собрано / 16 в окне / 2 живых. 65 кандидатов простаивают. Живость по urltest в отбор
окна не заводится (`MergePool.alive = Misses < poolMissesBeforeDrop` — это «не пропал из
подписки»), а у igareck строка всегда в файле → мёртвый держит слот вечно.

## Что сделать
1. `internal/lists/pool.go` — `PoolConfigServers` 16 → **64**. Обновить комментарий
   (обоснование: каталог живость igareck не отражает, поэтому окно должно быть широким,
   чтобы urltest нашёл живых сам; данные стенда 81/16/2).
2. `internal/singbox/pool.go` — `poolMaxServers` 16 → **64**, согласованно с (1).
   Обновить комментарий на `:30` (16 не переживают отказ большинства у igareck; 64 дают
   urltest живой резерв; цена — 64 outbound'а и 64 пробы каждые `PoolTestInterval`, это копейки).
3. Проверить, что два числа НЕ разъезжаются логически: lists кладёт до `PoolConfigServers`
   в состав, singbox эмитит до `poolMaxServers`. Оба = 64.
4. Тесты, завязанные на размер окна (напр. `TestMergePoolNewcomerWaitsBehindWindow`,
   `TestMergePoolFreezesKnownCards`, `TestMergePoolReplacesOnlyAfterRepeatedMiss` в
   `internal/lists/pool_test.go` — они генерят `poolCards(20)` и полагаются на окно 16):
   поправить так, чтобы они по-прежнему проверяли СВОЮ инвариантику (окно/очередь/выселение)
   при новом размере — либо увеличить наборы карт, либо параметризовать от `PoolConfigServers`,
   не хардкодя 16. Не удалять проверки, только адаптировать. Аналогично в `internal/singbox`,
   если есть тест на `poolMaxServers`.
5. Проверить `docs/decisions/` (0010, 0018) и docs — не зафиксировано ли число 16 как решение.
   Если только в комментариях кода — обновить их. Отдельный ADR под тюнинг-константу заводить
   НЕ надо (это не смена решения «пул на urltest» / «единый пул», а размер окна).

## Инварианты
- Клиентские инварианты (MTU 1280, DNS 10.8.0.1, FakeIP, ipv4_only) НЕ трогать — правится
  только размер пула.
- Конфиг sing-box генерируется целиком + `sing-box check` — не ломать.
- `CGO_ENABLED=0`, netlink-путь не затрагивается.

## Критерии приёмки
- `PoolConfigServers == poolMaxServers == 64`.
- `go build ./...`, `go test ./...` зелёные; gofmt чисто; CI зелёный до мержа.
- Проверка на стенде 186.246.29.11 (оркестратор после мержа): в ротации до 64, живых
  заметно больше 2. **Только стенд.**

## Слои
lists (размер окна MergePool), singbox (потолок outbounds пула).
