## TLDR

Пакет `internal/netstack`: таблица `inet razdacha` (цепочки `mangle`, `proxy`,
`forward`, `postrouting`, сеты `local_v4` и `razdacha_subnets`), маркировка
`0x00100000`, `tproxy` на `127.0.0.1:1602`, masquerade на WAN и policy routing
`fwmark → таблица 105 → local dev lo`. Только `google/nftables` и
`vishvananda/netlink`, ни одного вызова `nft`, `ip`, `iptables`.

## Goal

Вторая половина слоя `netstack`: помеченный трафик клиентов доходит до sing-box,
остальное уходит напрямую через masquerade, а снятие возвращает систему в
исходное состояние.

## Domains touched

- [netstack](../context/netstack/index.md) — nft-таблица, маркировка, таблица 105
- [lists](../context/lists/index.md) — источник подсетей для `razdacha_subnets`

## Decisions

- 2026-07-25 — набор правил описывается своим типом (`NftRuleset`), а перевод в
  выражения nftables вынесен в файл под `//go:build linux`. Причина не только в
  тестах: `google/nftables` тянет `unix.NFPROTO_*` и не собирается вне linux, а
  состав правил проверять хочется на любой машине.
- 2026-07-25 — заливка идёт одним пакетом изменений: `DelTable` прежней таблицы,
  создание новой, сеты и правила уходят в ядро одной транзакцией `Flush`. Окна,
  в котором правил нет и трафик уходит мимо туннеля, не возникает.
- 2026-07-25 — существование таблицы проверяется отдельным чтением до пакета:
  удаление отсутствующей таблицы отменяет весь пакет, включая создание новой.
- 2026-07-25 — подсети сливаются в непересекающиеся интервалы через
  `go4.org/netipx`. `auto-merge` из документации — приём userspace-утилиты `nft`,
  через netlink его нет, а пересекающиеся интервалы (Cloudflare и Telegram
  пересекаются) ядро отвергает вместе со всей транзакцией.
- 2026-07-25 — вместо `mangle_output` Podkop цепочки нет: у нас исходящий трафик
  сервера не проксируется (ADR 0002), достаточно `iifname != wg0 return`.
- 2026-07-25 — имя таблицы в `/etc/iproute2/rt_tables` не пишется, в отличие от
  Podkop (`bin/podkop:254`): через netlink нужен только номер, а правка чужого
  файла — след, который потом приходится убирать.
- 2026-07-25 — WAN определяется по маршруту по умолчанию (`DetectWAN`), из
  нескольких берётся маршрут с наименьшей метрикой. Пользователю интерфейс
  задавать не нужно.

## Acceptance criteria

- [x] только netlink: `google/nftables` и `vishvananda/netlink`
- [x] перезаливка правил атомарная — один `Flush` на всё изменение
- [x] прямой трафик не заходит в sing-box: `tproxy` возможен только по метке,
      метка ставится только по совпадению адреса назначения
- [x] IPv6 клиентов отклоняется `reject with icmpv6 admin-prohibited` (ADR 0005),
      других правил по ipv6 в наборе нет
- [x] снятие убирает таблицу, правило маршрутизации и содержимое таблицы 105;
      повторное снятие на чистой системе — не ошибка
- [x] чистая логика тестируется без root: состав правил, наполнение сетов из
      `lists.ParsePlain`, идемпотентность сборки, подмена netlink интерфейсом
