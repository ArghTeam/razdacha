## TLDR
Проверка туннелей идёт только по кнопке, а результат живёт в памяти, поэтому
экран туннелей всегда встречает пользователя пустыми полями. Заводим расписание
поверх Clash API и храним последний статус — без latency, она за минуты врёт.

## Goal
Статусы туннелей заполнены без участия пользователя и переживают перезапуск демона.

## Domains touched
- [api](../context/api/) — кэш проверок, расписание, клиент Clash API
- [store](../context/store/) — хранение последнего статуса, ключ интервала в настройках

## Decisions
- 2026-07-27 — проверяем через `clash.Delay()`, своей проверялки не заводим:
  инвариант слоя api требует читать состояние у той же группы `urltest`, по
  которой реально переключается трафик, иначе панель и трафик разойдутся.
- 2026-07-27 — храним статус и время, latency не храним. Решение в
  `internal/api/tunnels_check.go:33` («в БД не пишутся намеренно») остаётся
  верным для задержки — она живёт минуты — и неверным для статуса: «был down в
  06:40» рядом с временем полезен. Уточнение оформляется отдельным ADR.
- 2026-07-27 — конвенция «`null` = никто не проверял» не меняется. После первого
  цикла расписания null просто перестаёт быть нормой, но остаётся честным
  ответом до него.
- 2026-07-27 — расписание списывается с `internal/lists/manager.go`: Start,
  loop, учащённый повтор после неудачного прогона.

## Acceptance criteria
- [ ] После старта демона статусы заполняются без нажатия «Проверить»
- [ ] Статус и время переживают перезапуск демона, latency — нет
- [ ] Интервал проверки настраивается, дефолт задокументирован
- [ ] Заведён ADR, явно называющий, что он уточняет
- [ ] Удалённый туннель не держит за собой запись о проверке
