## TLDR

Панель уходит за nginx. `razdachad` слушает `127.0.0.1:8080`, nginx — `10.8.0.1:443`
и `10.8.0.1:80` (редирект). Конфиг nginx генерируется кодом из `SiteConfig`,
самоподписанный сертификат выпускается средствами Go в `/etc/razdacha/tls/`.
Установка и удаление идемпотентны и не трогают чужие файлы в `/etc/nginx`.
Модель доступа не меняется: панель по-прежнему видна только из VPN (ADR 0001).

## Goal

Установщик сам поднимает единую точку входа на адресе wg0 — с TLS, без порта в
URL и с работающим WebSocket, — а демон перестаёт зависеть от готовности `wg0`
при старте.

## Decisions

- 2026-07-25 — [ADR 0008](../docs/decisions/0008-nginx-before-panel.md): nginx
  перед панелью, демон на loopback. Решение 0001 остаётся в силе — nginx привязан
  к адресу `wg0`, а не к `0.0.0.0`. Смысл TLS здесь не в защите трафика (он и так
  внутри WireGuard), а в снятии браузерных ограничений «secure context» и
  подготовке к возможному публичному режиму.
- 2026-07-25 — адрес nginx проверяется белым списком «приватный, loopback или
  link-local», а не чёрным списком из одного `0.0.0.0`: чёрный список закрывает
  ровно один способ ошибиться из многих. Публичный адрес даёт `ErrPublicListen`
  до генерации текста. Тот же белый список — на upstream: только loopback.
- 2026-07-25 — конфиг собирается `text/template` из `SiteConfig`; пути к
  сертификату и ключу проверяются на пробелы, `;`, кавычки и скобки —
  экранировать их для nginx дороже, чем запретить.
- 2026-07-25 — HTTP/2 не включаем: директива меняла форму между nginx 1.22
  (Debian 12) и 1.25. `proxy_buffering off` и `proxy_read_timeout 3600s` — по
  `/api/ws` между сообщениями законно проходят минуты, дефолтные 60 с рвали бы
  соединение, а UI показывал бы это как «зависло».
- 2026-07-25 — свой файл помечается маркером в первой строке. Файл без маркера по
  нашему пути считается чужим: установка останавливается с `ErrForeignConfig` и
  ничего не перезаписывает, удаление такой файл оставляет. То же для symlink —
  снимается только тот, что ведёт на наш файл.
- 2026-07-25 — сертификат ECDSA P-256 средствами Go (`openssl` не вызываем — на
  минимальном образе его может и не быть), срок 10 лет, перевыпуск только если
  файла нет, он не разбирается, истекает в ближайший месяц или не покрывает
  нужный IP: пользователь добавляет его в исключения браузера руками, и смена на
  каждой установке эту работу обнуляла бы.
- 2026-07-25 — корень файловой системы вынесен в поле `Installer.Root`: пути
  внутри продуктовые, в работе `Root` пустой, в тестах — `t.TempDir()`. Symlink
  указывает на путь с учётом корня, поэтому ссылка разрешается в обоих случаях.
- 2026-07-25 — `Install` только пишет файлы; `systemctl reload nginx` и
  `apt install nginx` остаются за `install.sh`. Отсутствие каталогов nginx — не
  паника, а `ErrNginxNotInstalled` с командой установки пакета.
- 2026-07-25 — сертификат при удалении не трогается: он в `/etc/razdacha` и
  уходит вместе с ним.
- 2026-07-25 (по итогам стенда, Debian 13 / nginx 1.26.3) — `Install` снимает
  `sites-enabled/default`. Пакет nginx включает его сам, слушает он
  `0.0.0.0:80` и `[::]:80`: критерий «не слушает публичный адрес» выполнялся на
  уровне нашего файла и нарушался на уровне системы. Снимается только symlink на
  `sites-available/default` (абсолютный или относительный); файл пакета и чужой
  symlink с тем же именем не трогаются.
- 2026-07-25 — факт снятия записывается отметкой
  `/etc/razdacha/nginx-default-disabled.json`, и возврат идёт по ней, а не по
  догадке: по отсутствию symlink не отличить «сняли мы» от «пользователь снял
  сам». Отметка пишется до снятия — лишняя безобиднее потерянной.
- 2026-07-25 — `net.ipv4.ip_nonlocal_bind=1` кладётся в тот же
  `/etc/sysctl.d/99-razdacha.conf`, что и `ip_forward`: параметры появляются и
  исчезают вместе с razdacha, и разносить их по двум файлам значило бы удалять
  их в двух местах. Без него nginx не стартует, пока демон не создал `wg0` —
  проверено на стенде, юнит уходит в `failed`. `After=` как единственное решение
  не годится: демон может стартовать раньше, чем поднимется `wg0`.
- 2026-07-25 — параметры пишутся и в drop-in (переживает перезагрузку), и сразу в
  `/proc/sys` (не ждать её); `sysctl` бинарником не вызывается — это обычные
  файлы. Отсутствие `/proc/sys` — предупреждение, а не ошибка.

## Acceptance criteria

- [x] nginx не слушает ни одного публичного адреса ни в одной ветке кода —
      проверено тестом: в тексте нет `0.0.0.0`, `[::]` и `listen` без адреса,
      публичный адрес в настройках даёт ошибку; дефолтный сайт Debian, который
      слушал `0.0.0.0:80`, снимается установкой
- [x] WebSocket проходит через прокси: `proxy_http_version 1.1`, `Upgrade`,
      `Connection` через `map` — закреплено тестом
- [x] генерация конфига покрыта тестами на рендеринг, живой nginx не нужен
- [x] повторная установка не плодит дубликаты и не ломает существующий конфиг
- [x] удаление снимает symlink и наш файл, чужие оставляет на месте
- [x] `docs/01-architecture.md`, `docs/05-api.md`, `docs/08-install-upgrade.md` и
      ADR 0008 отражают изменение
- [x] стенд (Debian 13, nginx 1.26.3): `nginx -t` проходит, TLS-хендшейк идёт,
      80 отдаёт 301, до апстрима доходят `Upgrade`/`Connection` и `X-Real-IP`,
      повторная установка ничего не меняет, удаление не трогает чужое
- [x] найденное на стенде исправлено: снятие `sites-enabled/default` и
      `ip_nonlocal_bind`
- [ ] перепроверка на стенде после правок — см. отчёт: `ss -tulpn` без
      `0.0.0.0:80`, `curl` по публичному адресу без ответа, `systemctl restart
      nginx` при снятом адресе `10.8.0.1`, возврат дефолтного сайта после
      удаления
