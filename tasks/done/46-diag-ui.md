## TLDR

Экран диагностики показывает ход проверки: «Проверить заново» прогоняет семь
проверок по одной через `POST /api/diag/run?check=<id>`, строки обновляются по
мере ответа, кнопка на время прогона выключена и считает шаги, время последней
проверки приходит с сервера полем `checked_at`.

## Goal

Нажатие «Проверить заново» видно: пользователь понимает, что проверка идёт,
какая проверка выполняется сейчас и сколько осталось, а результат появляется
построчно, а не рывком в конце.

## Domains touched

- [ui](../context/ui/index.md) — экран диагностики, стили хода проверки
- [api](../context/api/index.md) — прогон одной проверки, `checked_at`

## Decisions

- 2026-07-26 — выбран вариант (б): `POST /api/diag/run?check=<id>` прогоняет
  одну проверку, панель идёт по семи идентификаторам последовательно.
  Оптимистичное «проверяется» на всех строках (вариант а) — та же анимация
  вместо хода: строки раскрываются разом, и «какая идёт сейчас» показать
  нечем, а при сбое одной проверки непонятно, какой именно. Стриминг
  (вариант в) требует SSE или сообщения в WS ради семи локальных проверок,
  которые целиком укладываются в секунду, — цена не окупается. Плата за (б) —
  семь запросов вместо одного; они локальные (netlink, sysctl, генерация
  конфига), наружу не ходят.
- 2026-07-26 — общий статус при прогоне по одной считает панель: сервер,
  выполнив одну проверку, видит только её. Правило то же, что в
  `docs/05-api.md` — худший статус, `unknown` хуже `ok`, но лучше `warn`.
- 2026-07-26 — время последней проверки отдаёт сервер (`checked_at`), а не
  часы браузера. Раньше UI подставлял `new Date()`, и любой снимок выглядел
  сделанным только что — в том числе пришедший из живого канала.
- 2026-07-26 — перечень и порядок проверок панель берёт из последней сводки, а
  не из зашитого списка: набор проверок задаёт демон, зашитый перечень
  разъехался бы с ним при первой же новой проверке.
- 2026-07-26 — прогон одной проверки читает только нужные ей источники: `mtu`
  не дёргает nftables, `nft` не читает sysctl.
- 2026-07-26 — не ответившая проверка получает `unknown` с причиной в строке, а
  прошлый результат не остаётся: невыполненная проверка — это не «всё хорошо».
- 2026-07-26 — `load()` экрана не подменяет строки снимком с сервера, пока идёт
  прогон: фоновый опрос раз в 15 секунд иначе затирал бы ход.

## Acceptance criteria

- [x] `POST /api/diag/run?check=<id>` возвращает одну проверку; неизвестный
      `id` — `400`, а не пустая сводка
- [x] `GET /api/diag` и прогон отдают `checked_at`; UI показывает время из него
      либо честное «время проверки неизвестно»
- [x] на время прогона кнопка выключена и показывает «Проверяю… N / 7»,
      повторные нажатия не плодят запросов (проверено: ровно 7 POST на прогон)
- [x] ещё не ответившая строка говорит «проверяется…» или «в очереди», а не
      показывает прошлый результат
- [x] проверка, ответившая ошибкой, становится `unknown` с текстом ошибки
- [x] полоса хода и крутилки работают в тёмной и светлой темах и на телефоне
- [x] `POST /api/diag/run` без параметра работает по-прежнему — запасной путь,
      когда сводки на экране ещё нет

## Не сделано

- Живой канал (`diag` в WS) в ходе прогона не участвует: панель спрашивает
  сама и рисует свои же ответы.
- Отмены прогона нет — семь проверок укладываются в секунды, кнопка «Отмена»
  добавила бы состояние ради состояния.
- Времени по каждой строке отдельно нет: `checked_at` один на сводку.
