## TLDR

Слой хранения: схема SQLite для четырёх сущностей (Tunnel, Rule, Peer, Settings)
по наброску `docs/02-data-model.md:133-158`, версионированные идемпотентные
миграции и CRUD-доступ. `modernc.org/sqlite`, сборка при `CGO_ENABLED=0`.

## Goal

Дать остальным слоям единственный источник состояния — БД, из которой
`internal/singbox` целиком генерирует конфиг.

## Domains touched

- [store](../context/store/index.md) — схема, миграции, хранение ключей пиров

## Decisions

- 2026-07-25 — `modernc.org/sqlite` пинуется на `v1.38.2`, а не `latest`: свежие версии
  требуют `go 1.25` и при `go get` поднимают директиву в `go.mod`, а конституция
  фиксирует «Go ≥ 1.23» (зависимость `sing-box/option`).
- 2026-07-25 — приоритет правил назначает слой хранения, а не вызывающий: иначе
  уникальный индекс `rules_priority` ловил бы пользовательский ввод. Порядок меняется
  отдельной операцией с полным списком идентификаторов.
- 2026-07-25 — добавлен `Snapshot` сверх объёма задачи: конфиг sing-box генерируется
  целиком, чтение состояния по частям пустило бы в конфиг правило на туннель,
  удалённый между запросами.
- 2026-07-25 — из этой же ветки убран бинарник `razdachad`, случайно закоммиченный
  вместе с настройкой CI (#1).

## Acceptance criteria

- [x] `modernc.org/sqlite`, сборка проходит при `CGO_ENABLED=0` (не `mattn`)
- [x] удаление туннеля, на который ссылается правило, отклоняется внятной
      ошибкой на русском (`ON DELETE RESTRICT`, а не тихая поломка маршрутизации)
- [x] повторный прогон миграций на актуальной БД ничего не меняет
- [x] уникальность `rules.priority` соблюдается при переупорядочивании
- [x] тесты идут на временной БД, без внешних зависимостей и root
