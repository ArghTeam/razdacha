# 60 — установщик называет адрес, по которому панель действительно открывается

Issue: [#60](https://github.com/ArghTeam/razdacha/issues/60) · слои: packaging

## Цель

В публичном режиме (`RAZDACHA_PUBLIC=1`) установщик всё равно печатает `https://10.8.0.1`.
Панель при этом слушает и внешний адрес. Пользователь идёт по названному адресу, не
попадает туда без VPN и решает, что публичный режим не включился.

## Решение

В публичном режиме первым называется внешний адрес, вторым — `10.8.0.1` для тех, кто уже
в VPN. В обычном режиме вывод прежний.

К выводу добавляется строка о том, как переключить режим: переменная существует, но о ней
надо знать заранее, а узнаёт о ней человек как раз в этот момент.

## Что осталось за границей и почему

Issue предлагает подумать шире: спрашивать режим при установке вместо переменной
окружения. Отклонено, и не по вкусу, а по способу установки: установщик запускается как
`curl -fsSL … | sh`, у него stdin занят пайпом. Интерактивный вопрос там пришлось бы
читать из `/dev/tty`, которого нет ни в CI, ни при запуске из скрипта, а молчаливый
дефолт при отсутствии tty вернул бы ровно сегодняшнюю ситуацию — только менее
предсказуемо.

Поэтому [ADR 0009](../docs/decisions/0009-public-panel-access.md) остаётся в силе, нового
решения не заводится. Задача сводится к тому, чтобы вывод не врал и называл переключатель.

## Критерии приёмки

- [x] В публичном режиме первым напечатан внешний адрес, вторым — `10.8.0.1` с пометкой,
      что он для тех, кто уже подключён
- [x] В обычном режиме вывод не изменился
- [x] В обоих режимах сказано, как переключить режим (`RAZDACHA_PUBLIC=1` / `=0`)
- [x] Внешний адрес берётся не из догадки: если определить его нечем, печатается честная
      формулировка, а не выдуманный адрес (инвариант «пустота не заполняется выдумкой»)

## Decisions

- 2026-08-15: интерактивный вопрос при установке не заводится — `curl | sh` не оставляет
  для него stdin; ADR 0009 остаётся в силе.
