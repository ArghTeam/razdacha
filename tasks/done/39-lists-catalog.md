## TLDR

`GET /api/lists/community` отдаёт каталог сервисов allow-domains, планировщик
`lists.Manager` поднимается вместе с демоном, а подсети из скачанных списков
уходят в сет `razdacha_subnets` наравне с ручными и перезаливаются после каждого
прогона.

## Goal

Списки сервисов появляются в панели: при создании правила есть что выбрать, а
выбранное действительно попадает в nft-сет.

## Domains touched

- [api](../context/api/index.md) — новый маршрут каталога
- [lists](../context/lists/index.md) — каталог ключей, проводка планировщика
- [netstack](../context/netstack/index.md) — перезаливка сета по обновлению

## Decisions

- 2026-07-26 — каталог статический и живёт в `internal/lists/catalog.go`: он
  описывает состав чужого репозитория allow-domains, а не состояние демона.
  Состав и порядок — как у Podkop (`files/usr/lib/constants.sh:66`), названия на
  русском, `has_domains` у всех (`.srs` собирается на каждый ключ,
  `files/usr/bin/podkop:1002`), `has_subnets` берётся из `communitySubnets` —
  того же признака, по которому планировщик решает, что качать.
- 2026-07-26 — эндпоинт не зависит ни от БД, ни от загруженных списков: при
  недоступном GitHub панель обязана показать галочки, иначе правило не собрать.
- 2026-07-26 — планировщик поднимает `startLists` в `cmd/razdachad/lists.go`, и
  ни одна его неудача демон не останавливает: не открылся кэш — возвращается
  `nil` и шлюз работает на ручных подсетях, не скачался список — повтор с
  нарастающей паузой внутри слоя. Кэш — `<каталог БД>/lists`, отдельного флага
  нет.
- 2026-07-26 — набор источников сверяется с БД раз в 30 с (`syncListSources`),
  как `syncWGPeers`: правила приходят через REST, и до событийной перевыдачи
  (issue #30) иначе про новое правило планировщик не узнает. Изменившийся набор
  дозагружается сразу, а не через сутки.
- 2026-07-26 — `startNetfilter` принимает планировщик и подписывается на
  `Manager.Updates()`: после каждого прогона таблица перезаливается целиком
  одним `Flush` (инвариант слоя netstack), потому что сет — часть таблицы и
  отдельно от неё не обновляется. Неудачная перезаливка только пишется в лог: в
  ядре остаётся прежняя таблица, следующий прогон попробует снова.

## Acceptance criteria

- [x] панель показывает список сервисов при создании правила — `state.missing`
      больше не выставляется, UI рисует галочки из ответа
- [x] загрузка списков не задерживает старт демона — `Manager.Start` уводит
      первый прогон в горутину
- [x] обновление сета не рвёт соединения — перезаливка одной транзакцией
- [x] неудача загрузки не роняет демон и видна в логе
- [x] тесты без сети: каталог под сессией и 401 без неё, подсети из списков в
      наборе для nft, планировщик продолжает работу после провального прогона
