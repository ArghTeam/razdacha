## TLDR

Интерфейс `wg0` и его пиры целиком через netlink: `vishvananda/netlink` для
интерфейса, `wgctrl` для устройства. Ключи сервера заводятся при первом
поднятии и лежат в БД рядом с ключами пиров; пиры синхронизируются диффом, а не
перезаливкой; статистика с интерфейса заполняет производные поля API, которые до
сих пор были `null`. Генерация клиентского конфига переехала из `api` в
`netstack` — источник шаблона теперь один.

## Goal

Без `wg0` демон не делает ничего: клиенты не подключаются, публичного ключа для
конфига нет, панель показывает пиров, которых нигде не существует. Файла
`/etc/wireguard/wg0.conf` у нас нет и `wg-quick` не вызывается — состоянием
владеет демон, иначе перевыдать пира без разрыва чужих сессий невозможно.

## Domains touched

- [netstack](../context/netstack/index.md) — `wg0`, ключи сервера, дифф пиров,
  статистика, клиентский конфиг
- [store](../context/store/index.md) — приватный ключ сервера как key/value рядом
  с хешем пароля панели

## Decisions

- 2026-07-25 — **приватный ключ сервера в таблице `settings`**, ключ
  `wg_server_private_key`, вне структуры `Settings`. Ровно как хеш пароля:
  `SaveSettings` пишет только свои ключи, `Settings` игнорирует чужие, поэтому
  сохранение настроек из панели ключ не затирает и в `GET /api/settings` он не
  утекает. Отдельный файл с секретом завёл бы второе место хранения и второй
  набор прав — у БД они уже `0600`.
- 2026-07-25 — **ключ создаётся в `Up`, а не при чтении публичного**.
  `WGServerPublicKey` только читает: генерация по запросу из панели выдала бы
  ключ, которого нет ни на одном интерфейсе, и клиент с таким конфигом молча не
  подключался бы. Нет ключа — API честно отдаёт `null`.
- 2026-07-25 — **синхронизация диффом**. `wgDiffPeers` сравнивает набор из БД с
  дампом устройства и пишет только расхождения: добавление, `UpdateOnly` при
  изменении, `Remove` при исчезновении. Перезалив (`ReplacePeers`) снял бы и
  завёл заново всех, включая тех, у кого ничего не менялось, — это разрыв живых
  хендшейков на каждую правку. По той же причине приватный ключ и порт в `Up`
  переписываются только при расхождении.
- 2026-07-25 — **root и netlink спрятаны за `wgLinkOps` и `wgDeviceOps`**. Дифф,
  разбор ключей, сборка клиентского конфига и параметры интерфейса из настроек —
  чистые функции; тесты гоняют менеджер целиком на фейках, без привилегий и без
  ядра. Реализация netlink — под `//go:build linux`, на остальных платформах
  заглушка с `ErrWGUnsupported`: демон Linux-only, но собираться и тестироваться
  проект обязан везде.
- 2026-07-25 — **клиентский конфиг генерирует `netstack`**, `api` его только
  отдаёт. Шаблон из `docs/03-networking.md` описывает интерфейс WireGuard, а не
  HTTP-контракт; два места сборки одного файла разъехались бы на первой правке.
- 2026-07-25 — **интерфейс не снимается при остановке демона**. `Up` идемпотентен
  и переживает рестарт, снимать `wg0` на каждый `systemctl restart` — рвать
  клиентам связь на ровном месте. `Down` есть и вызывается осознанно: удаление
  пакета и `--reset-network`.
- 2026-07-25 — **пиры сверяются по таймеру (10 с)** в `cmd/razdachad` до тех пор,
  пока не приедет событийное применение конфига (#30). Сверка диффом на
  неизменном состоянии не выполняет ни одной записи, поэтому цена опроса —
  один дамп устройства.

## Acceptance criteria

- [x] MTU интерфейса ровно 1280 и берётся из настроек, где дефолт — 1280
      (ADR 0004); значение вне 576–1500 отклоняется до netlink
- [x] `wg`, `wg-quick`, `ip` не вызываются: интерфейс — `vishvananda/netlink`,
      устройство — `wgctrl`
- [x] выключенный пир снимается с `wg0` и остаётся в БД со всеми ключами
- [x] повторная синхронизация неизменного состояния не пишет в устройство ничего
- [x] клиентский конфиг всегда содержит `DNS = 10.8.0.1`, `MTU`,
      `AllowedIPs = 0.0.0.0/0, ::/0`, `PersistentKeepalive = 25` и `PresharedKey`
- [x] дифф пиров и сборка конфига проверяются тестами без root и без netlink
- [x] `last_handshake`, `rx_bytes`, `tx_bytes`, `endpoint` и `online` доезжают
      до `GET /api/peers`; пира нет на интерфейсе — поля остаются `null`
