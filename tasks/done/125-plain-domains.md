# 125 — домены plain-списков доезжают до конфига

Issue: [#125](https://github.com/ArghTeam/razdacha/issues/125) · слои: lists, singbox

## Цель

Внешний список правила не в формате `.srs`/`.json` качался и разбирался слоем lists, а
наружу отдавались только подсети — `List.Domains` не использовал никто. Правило, у
которого такой список единственный, оставалось без единого условия совпадения и выпадало
из конфига: его трафик забирал `route.final`, то есть прямой выход с адреса сервера.
После [ADR 0013](../docs/decisions/0013-unavailable-tunnel-rejects.md) это был последний
путь тихой утечки — все прочие пропуски стали отказами.

## Решение

Вариант 1 из issue: содержимое plain-списка уходит в `inline`-набор правила.

- слой lists уже качает и разбирает такие списки — не хватало пути наружу;
- `docs/04-dns-fakeip.md` обещал «иное → plain, скачиваем сами», то есть документ обещал
  то, чего код не делал;
- вариант 2 (отказывать при сохранении) закрыл бы заодно и подсети plain-списков: они
  попадают в nft-сет, но без набора в конфиге sing-box выпускает их напрямую — то есть
  отказ пришлось бы выдавать на работающий сегодня сценарий.

Домены и подсети идут двумя записями одного набора — как у своих доменов правила. Тег
`rule-<id>-plain-<i>` отличается от `rule-<id>-remote-<i>`: у правила бывают оба вида
списков при общей нумерации `RemoteLists`.

Содержимое доезжает до генератора замыканием `singbox.PlainLists`, которое даёт демон
(`cmd/razdachad/lists.go`) — тем же приёмом, каким слою api достаётся заливка nft. Слой
singbox про кэш списков не знает.

## Критерии приёмки

- [x] правило с plain-списком доменов маршрутизирует эти домены в туннель;
- [x] списка ещё нет — пропуск правила громкий: `log.Warn` с адресом списка и причина в
      диагностике вместо общей «нет ни доменов, ни подсетей, ни списков»;
- [x] документация и код говорят одно и то же (`docs/04-dns-fakeip.md`, инварианты слоёв).

## Что осталось открытым

Правило без условий совпадения по-прежнему достижимо:

1. правило, не заполненное ничем: `Rule.validate` такое пропускает. Диагностика зовёт это
   ошибкой, сохранение — нет;
2. plain-список ещё не в кэше на момент сборки конфига (первый прогон не закончился,
   источник недоступен, кэш не открылся, новый список не подхвачен 30-секундной сверкой);
3. plain-список скачан, но пуст по существу — все строки отброшены разбором.

Случаи 2 и 3 теперь названы вслух, но правило всё равно вне конфига: выразить его нечем
(ADR 0013). Свежескачанное содержимое доезжает до sing-box следующим применением
конфигурации — расписание списков применять её за пользователя не вправе, вместе со
списком уехали бы и не применённые им правки правил (issue #30).
