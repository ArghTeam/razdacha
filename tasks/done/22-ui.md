## TLDR

Интерфейс панели: экран входа и четыре экрана прототипа, подключённые к живому API.
Статика без сборщика в `ui/dist`, встраивается через `go:embed` из нового пакета `ui`,
отдаётся слоем `api` на всех путях вне `/api/`. Весь доступ к серверу — через один
модуль `ui/dist/js/api.js`; ненаписанный эндпоинт отдаёт `404`, и экран говорит «данные
появятся позже» вместо пустого списка и выдуманных чисел.

## Goal

Владелец заходит браузером на адрес панели, вводит выданный установщиком пароль и
управляет клиентами, туннелями, правилами и диагностикой. Неавторизованный не видит
ничего, кроме формы входа.

## Decisions

- 2026-07-25 — **без SvelteKit, вопреки «Stack» в AGENTS.md.** Причины три, и все
  практические. Первая: `node` в этом окружении не поднимается, а панель обязана
  собираться одной командой `go build` — сборщик, который нельзя запустить, это не
  сборщик. Вторая: в прод уезжает `ui/dist`, встроенный в бинарник; ни `node_modules`,
  ни `.svelte-kit` туда не едут, то есть весь выигрыш фреймворка тратится на этапе, в
  цепочке сборки демона отсутствующем. Третья: прототип (`ui/prototype/`, 1261 строка
  ванильного JS вместе с собственным QR-кодером) уже доказал, что четырёх экранов и
  формы входа хватает без реактивного фреймворка — переписывание дало бы те же экраны
  дороже. Замена не в архитектуре, а в инструменте: раскладка `ui/` → `go:embed`
  сохранена, интерфейс по-прежнему один артефакт внутри бинарника. Строка «SvelteKit +
  Tailwind» в AGENTS.md и в `docs/06-ui-screens.md` этим решением заменяется.
- 2026-07-25 — модули ES без бандлера (`<script type="module">`), файлы в `ui/dist/js/`.
  Раз бандлера нет, разделение на файлы делает браузер, и это допустимая цена: панель
  открывается по локальной сети или через nginx с HTTP/2, десяток мелких файлов ничего
  не стоит.
- 2026-07-25 — один слой доступа к API (`ui/dist/js/api.js`). Эндпоинты пишет
  параллельная задача по тому же `docs/05-api.md`; расхождение контракта и реализации
  должно чиниться в одном файле, а не по всем экранам.
- 2026-07-25 — вместо клиентской сборки `.conf` интерфейс просит его у демона
  (`GET /api/peers/{id}/config`), а QR рисует сам из полученного текста. Причина —
  дыра контракта, найденная прототипом: публичного ключа сервера нет ни в одной
  сущности API, и собрать конфиг на клиенте нечем. Заодно отпадает нужда в
  `GET /api/peers/{id}/qr`.
- 2026-07-25 — ненаписанный эндпоинт отличается от пустых данных по `404`. Экран
  показывает «данные появятся позже» с указанием пути. Пустой список на месте
  неизвестного — это враньё, которое пользователь примет за поломку своей настройки.
- 2026-07-25 — статика не требует сессии, всё под `/api/` требует. Иначе экран входа
  пришлось бы отдавать по особому правилу, а именно он и есть та страница, куда
  пользователь вводит пароль. Обратное правило важнее: `/api/` не проваливается в SPA,
  иначе опечатка в пути REST вернула бы HTML со статусом `200`.
- 2026-07-25 — `//go:embed all:dist` плюс `ui/dist/.gitkeep`: директива без файлов —
  ошибка компиляции, а бинарник обязан собираться и с вычищенной статикой. Пустой
  каталог обрабатывается на рантайме — `503` с текстом причины, а не паника.
- 2026-07-25 — пароль не попадает никуда, кроме тела `POST /api/login`: у формы нет
  ни `action`, ни `method`, отправка идёт `fetch`, поле очищается и при успехе, и при
  отказе. При `429` кнопка блокируется на срок из `Retry-After` с обратным отсчётом.

## Acceptance criteria

- [x] неавторизованный запрос к любому экрану ведёт на вход, а не на пустой UI
- [x] пароль не попадает в историю браузера, в логи и в URL
- [x] после входа пользователь возвращается туда, куда шёл (проверено: `#rules` → 401 →
      вход → `#diag`)
- [x] сборка проходит в CI и результат встраивается в бинарник; при пустом `ui/dist`
      сборка не ломается
- [x] «четыре экрана» из vision сохранены: вход — гейт, а не пятый раздел
- [x] `/` и неизвестный путь отдают `index.html`, `/api/*` туда не проваливается,
      статика без сессии — `200`, API без сессии — `401` (`internal/api/static_test.go`)

## Что интерфейс ждёт от API

`GET/POST/PATCH/DELETE /api/peers` (+ `/{id}/config` как `text/plain`),
`GET/POST/PATCH/DELETE /api/tunnels` (+ `/parse`, `/{id}/check`),
`GET/POST/PATCH/DELETE /api/rules` (+ `PUT /api/rules/order`),
`GET /api/lists/community`, `GET/PATCH /api/settings`,
`GET /api/diag`, `POST /api/diag/run`, `GET /api/diag/singbox-config`, `GET /api/logs`,
`POST /api/apply`, `GET /api/apply/status`, `GET /api/ws`.

Три места, где контракт не закреплён и интерфейс принимает несколько форм:
`GET /api/apply/status` (`dirty` / `pending` / `has_changes`), `GET /api/logs` (текст,
массив строк или `{lines: []}`), `list_update_interval` (секунды или наносекунды
`time.Duration`). Нормализация — в `ui/dist/js/api.js` и `ui/dist/js/util.js`.
