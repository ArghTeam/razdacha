## TLDR

Пакет `internal/clash` — клиент Clash API sing-box: задержка по тегу
(`/proxies/<tag>/delay`), состояние прокси (`/proxies`, `/proxies/<tag>`), адрес
параметром. Наружу это выходит как `POST /api/tunnels/{id}/check`, а результат
последней проверки заполняет `status`, `latency_ms` и `last_check` в
`GET /api/tunnels`.

## Goal

Кнопка «Проверить» у туннеля отвечала «такого пути нет». Задача замыкает
единственный способ спросить работающий рантайм о туннеле — и делает это так,
чтобы три разные ситуации не слипались в одну ошибку: туннель не применён,
туннель применён и не работает, sing-box не отвечает вовсе.

## Domains touched

- [api](../context/api/index.md) — `internal/clash`, `POST /api/tunnels/{id}/check`,
  производные поля списка туннелей

## Decisions

- 2026-07-26 — тег строится тем же `singbox.TunnelTag(id)` (`tun-<id>`), что и в
  генераторе: своя копия правила означала бы проверку не того туннеля при первом
  же изменении схемы тегов.
- 2026-07-26 — три исхода Clash API разведены сентинелами: `ErrNotFound` (404) —
  «не применён», `ErrProbeFailed` (5xx с текстом) — «down», `ErrUnavailable`
  (отказ соединения, таймаут) — состояние демона, а не туннеля. Последний даёт
  `503 not_ready` и не пишет туннелю никакого статуса.
- 2026-07-26 — таймауты: `timeout=2000 мс` уходит самому sing-box (как в Podkop,
  `podkop/files/usr/bin/podkop:2260`), дедлайн HTTP-запроса — на три секунды
  больше. Порядок важен: первым обязан сработать sing-box, иначе «туннель не
  отвечает» и «sing-box не отвечает» превратились бы в один и тот же обрыв.
- 2026-07-26 — выключенный туннель не спрашивается вовсе: в конфиг он не
  попадает (`buildTunnels`), ответом был бы «не найден». Сразу `not_applied` с
  текстом «Туннель выключен».
- 2026-07-26 — результаты проверок лежат в памяти демона (`checkCache`), не в
  БД: задержка живёт минуты и после перезапуска sing-box уже ничего не значит.
  Пустой кэш — это `null` в производных полях, а не «down» и не «0 мс».
  Записи по удалённым туннелям вычищаются при чтении списка.
- 2026-07-26 — `GET /api/tunnels` сам никого не проверяет: список открывается на
  каждом переходе в панели, и десяток проверок по две секунды повесил бы экран.
  Проверка — только явная, по кнопке.
- 2026-07-26 — `clash.New` не возвращает ошибку: неверный адрес всплывёт первым
  же запросом как `ErrUnavailable`, а демон не должен отказываться стартовать
  из-за адреса вспомогательного API.
- 2026-07-26 — секрет Clash API поддержан заголовком `Authorization: Bearer`,
  хотя наш генератор его не ставит: `external_controller` с токеном — штатная
  конфигурация sing-box, и клиент не должен на ней ломаться.

## Acceptance criteria

- [x] проверка не блокирует панель: дедлайн запроса, `503` с русским текстом,
      если sing-box не отвечает
- [x] туннель, которого нет в работающем конфиге, отдаёт `not_applied` с
      объяснением, а не ошибку сети
- [x] тесты на `httptest`: Clash API подменяется, реальной сети нет — успех,
      таймаут, отсутствующий тег, мёртвый sing-box
- [x] поля `status`, `latency_ms`, `last_check` остаются `null`, пока проверки
      не было
- [x] `POST /api/tunnels/{id}/check` без сессии — 401
