## TLDR

Чистая функция «состояние БД → `option.Options`»: генератор конфига sing-box на
типизированных структурах, без конструирования JSON. Туннели ложатся в
`outbounds[]`/`endpoints[]`, правила — в `route.rules[]` по `priority`, DNS — с
FakeIP. Проверяется golden-тестами без сети и root.

## Goal

Сгенерировать целиком конфиг sing-box из состояния БД типизированными
структурами `option.Options`.

## Decisions

- 2026-07-25 — `sing-box` пинуется на `v1.12.25`, а не на 1.13/1.14: 1.13 требует
  `go 1.24` и поднял бы директиву в `go.mod` выше «Go ≥ 1.23» из конституции.
  ADR 0002 требует ≥ 1.12.0 — берём последнюю в этой линии.
- 2026-07-25 — наборы условий правила стали `inline`, а не `local` (доки обновлены):
  `local` держит условия в отдельных файлах рядом с конфигом, и их пришлось бы
  удерживать в согласии с ним при каждой правке. `inline` оставляет конфиг
  единственным артефактом на диске.
- 2026-07-25 — `action = block` получает запись и в `dns.rules[]` с `reject`.
  Одной записи в `route.rules` мало: без FakeIP домены блокируемого правила
  резолвятся в настоящие адреса, метка nft на них не ставится, и трафик уходит
  напрямую мимо sing-box, то есть мимо блокировки. Доки обновлены.
- 2026-07-25 — добавлен `experimental.cache_file` со `store_fakeip`: без него
  после перезапуска sing-box клиент с закэшированным FakeIP уходит в никуда.
- 2026-07-25 — правило пропускается, если у него не осталось условий совпадения
  или если выключены все выбранные им пиры: пустые `rule_set`/`source_ip_cidr`
  означают «совпадает со всем», то есть противоположность заданному. Ссылка на
  несуществующий туннель — ошибка, а не пропуск.
- 2026-07-25 — `sing-box/include` в тесты не берётся: пакет тянет весь sing-box
  (go.sum вырос бы с 69 до 287 строк ради проверки конфига). Реальная валидация —
  `sing-box check` перед применением, это задача слоя применения конфига.
- 2026-07-25 — разбор `raw` в `Tunnel.Parsed` не входит в задачу (парсеры proxy-URL
  — #4): генератор берёт `parsed` как есть, выбрасывая из него `type` и `tag`,
  которые проставляет сам.

## Acceptance criteria

- [x] `strategy: ipv4_only`, FakeIP только `inet4_range` (ADR 0005)
- [x] WireGuard-туннели попадают в `endpoints[]` в userspace-режиме, никаких
      kernel-интерфейсов и `bind_interface` (ADR 0002)
- [x] порядок `route.rules[]` соответствует `priority`: первое совпадение выигрывает
- [x] конфиг генерируется целиком из состояния, частичного патча нет
- [x] golden-тесты сравнивают полученный JSON с эталонами; сеть и root не нужны
