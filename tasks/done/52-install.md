## TLDR

`curl … | sh` доводит чистый Debian/Ubuntu до подключённого клиента. Скрипт держит
только фазу проверок и загрузку релиза; всё, что меняет систему, делает `razdacha
setup` — там уже лежит проверенный код `internal/packaging`. QR первого пира рисует
свой кодер на Go, портированный из панели. Релиз собирается по тегу `v*` и кладёт в
GitHub Releases два архива, `install.sh` и `checksums.txt`.

## Goal

На чистой машине одна команда доводит до состояния «клиент подключён и ходит в
интернет», повторный запуск обновляет, не трогая ключи и пиров, а `razdacha uninstall`
возвращает систему в исходное состояние. Отказ в фазе проверок оставляет систему
нетронутой.

## Domains touched

- [packaging](../context/packaging/index.md) — юниты systemd, install.sh, релиз по тегу
- [api](../context/api/index.md) — `CreatePeer` вынесена из обработчика наружу
- [netstack](../context/netstack/index.md) — снятие wg0, nft и маршрутов при удалении

## Decisions

- **Бинарник из GitHub Releases, не `.deb`.** Пакет требует `nfpm` в сборке и
  репозитория для обновлений; до первого релиза важнее, чтобы установка вообще
  существовала. Отсюда `/usr/local/bin` вместо `/usr/bin` — каталог не принадлежит
  пакетному менеджеру, `ExecStart` в юните подставляется по факту.
- **Ассеты названы без версии** (`razdacha-linux-amd64.tar.gz`). Иначе не работает
  `/releases/latest/download`, и скрипту пришлось бы ходить в API GitHub за номером
  последнего релиза — лишняя зависимость и лишний способ упереться в rate limit.
- **Граница «скрипт vs Go» проходит по фазам.** Проверки — shell: они выполняются до
  того, как бинарник окажется на машине. Изменения — Go: код nginx, TLS, sysctl и
  sing-box уже написан и покрыт тестами, вторая его реализация на shell отличалась бы
  собственным набором ошибок.
- **QR — свой кодер (`internal/qr`), не библиотека.** В `ui/dist/js/qr.js` уже лежит
  рабочий кодер, сверенный с `qrencode`; порт на Go — 400 строк без зависимостей в
  статическом бинарнике. Golden-векторы в `testdata/vectors.json` сняты с того самого
  JS-кодера, `testdata/qrencode.json` — с `qrencode`.
- **Сверка с `qrencode` не требует полного совпадения.** libqrencode считает правило 3
  штрафной функции (узор 1:1:3:1:1) не так, как написано в стандарте, и на части входов
  выбирает другую маску. Обе картинки валидны. Тест проверяет то, от чего это не
  зависит: хотя бы одна из восьми масок обязана дать матрицу байт в байт как у
  `qrencode` — значит совпали версия, поток данных, коррекция и раскладка по зигзагу.
- **`Type=notify` доведён до рабочего состояния.** Юнит в документе объявлял `notify`,
  а демон о готовности не сообщал — `systemctl start` висел бы до таймаута и объявлял
  юнит упавшим. Добавлен `cmd/razdachad/notify.go`: датаграмма `READY=1` в
  `$NOTIFY_SOCKET`, тридцать строк без зависимостей (`go-systemd` тянет d-bus).
  Готовность объявляется после подъёма `wg0` и заливки правил.
- **Юнит sing-box пишется, только если рантайм не пришёл пакетом.** Пакетный юнит
  обновляет пакетный менеджер, а наш файл в `/etc/systemd/system` перекрыл бы его
  навсегда. В своём юните **нет `ExecReload`**: `reload-or-restart` без него
  перезапускает сервис, а нужен именно перезапуск — кэш FakeIP обязан обнулиться
  вместе с конфигом.
- **`/etc/sing-box` в `ReadWritePaths`** — не для полноты: при `ProtectSystem=strict`
  без него запись конфига падает по правам, и в панели это выглядит как «внутренняя
  ошибка» на кнопке «Применить» (проверено на стенде).
- **`EndpointHost` дозаполняется установщиком** из маршрутизации. Настройка пустая по
  умолчанию, а без неё клиентский конфиг не собрать вовсе — первый пир не выдался бы.
- **Резервная копия БД снимается до открытия**, а не после: миграции накатываются в
  `store.Open` и назад не откатываются, вернуться можно только возвратом файла.
- **`ip_forward` при удалении не сбрасывается**, в отличие от `ip_nonlocal_bind`: его
  включают не только мы, и выключить его — значит оборвать чужую маршрутизацию на той
  же машине.
- **Вопросы удаления без терминала считаются отвеченными «нет»**: команда из скрипта не
  должна ни зависать на приглашении, ни удалять ключи оттого, что stdin пуст.
- **Бинарники при удалении остаются.** Команда работает из одного из них; удалять их
  из-под себя — лишний способ оборвать удаление на середине. Строку `rm -f …` печатает
  сама команда.

## Acceptance

- [x] `install.sh`: фаза проверок ничего не меняет, отказы копятся и печатаются разом
- [x] `--dry-run` / `RAZDACHA_DRY_RUN=1` — прогон одних проверок
- [x] повторный запуск — обновление; признак `state.db`, ключи и пиры сохраняются
- [x] `razdacha uninstall` снимает юниты, `wg0`, nft, sysctl, конфиг nginx и возвращает
      штатный сайт Debian; про `/var/lib/razdacha` спрашивает отдельно
- [x] QR печатается из Go, внешний `qrencode` не требуется
- [x] пароль панели генерируется и печатается один раз
- [x] релиз по тегу `v*`: `linux/amd64` и `linux/arm64`, `CGO_ENABLED=0`, версия из тега

## Проверка на стенде

```sh
# 1. проверки вхолостую — система не меняется
curl -fsSL .../install.sh | sh -s -- --dry-run
# 2. установка; в конце QR, пароль, адрес панели и строка про UDP-порт
curl -fsSL .../install.sh | sh
# 3. идемпотентность: тот же QR не печатается, пароль не меняется
sha256sum /var/lib/razdacha/state.db && curl -fsSL .../install.sh | sh
# 4. удаление
razdacha uninstall
```
