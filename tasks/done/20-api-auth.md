## TLDR

Первая задача слоя `api`: HTTP-сервер демона на `net/http` с graceful shutdown и
восстановлением после паники, авторизация по паролю (argon2id) с сессией в
cookie и блокировкой перебора по адресу клиента. Три эндпоинта — вход, выход,
статус сессии; всё остальное под `/api/` закрыто проверкой сессии.

## Goal

Панель после [ADR 0009](../docs/decisions/0009-public-panel-access.md) доступна
из интернета, и пароль становится единственной преградой к управлению
маршрутизацией всего трафика. Слой должен закрывать её так, чтобы ошибка не
стоила пользователю сервера: без пароля демон не стартует, сравнения постоянны
по времени, перебор упирается в блокировку, которую нельзя обойти заголовком.

## Domains touched

- [api](../context/api/index.md) — сервер, middleware, сессии, эндпоинты входа
- [store](../context/store/index.md) — таблица `sessions`, ключ `auth_password_hash`

## Decisions

- 2026-07-25 — argon2id `t=3, m=64 MiB, p=4, keyLen=32, salt=16` (второй набор
  RFC 9106): вариант на 2 GiB не живёт на VPS с 512 MiB. Параметры пишутся в
  сам хеш (формат PHC), поэтому их ужесточение не ломает старые пароли.
  Одновременных проверок не больше двух — иначе 64 MiB на попытку становятся
  вектором отказа.
- 2026-07-25 — сессии в БД, а не в памяти: перезапуск демона при обновлении не
  должен выкидывать всех из панели. В таблице лежит SHA-256 токена, сам токен
  (32 байта из `crypto/rand`) живёт только в cookie.
- 2026-07-25 — срок сессии сутки, продление на второй половине срока: продлевать
  на каждом запросе значило бы писать в БД на каждый опрос статистики.
- 2026-07-25 — адрес клиента берётся из `X-Real-IP`, затем из **последнего**
  элемента `X-Forwarded-For`, и только если соединение пришло с loopback. С
  любого другого адреса заголовки игнорируются: иначе блокировка обходится
  подделкой заголовка. Последний элемент, а не первый, потому что nginx
  дописывает реальный адрес в конец, а начало списка приходит от клиента.
- 2026-07-25 — пароль без сессии и сессия без пароля неразличимы по коду ответа:
  и то и другое `401`; блокировка — `429` с `Retry-After`.
- 2026-07-25 — `POST /api/logout` требует сессии, а `/api/` без маршрута отдаёт
  `401`, а не `404`: новый эндпоинт, который забудут закрыть, не станет дырой.
- 2026-07-25 — пароль задаётся `razdachad -set-password` из stdin, не аргументом
  командной строки: аргументы видны в `ps`.
- 2026-07-25 — смена пароля удаляет все сессии: увёденная cookie не должна
  переживать смену.

## Acceptance criteria

- [x] пароль нигде не хранится и не логируется в открытом виде
- [x] сравнение хешей пароля и токенов сессии — постоянное по времени
- [x] демон отказывается стартовать без заданного пароля
- [x] серия неудач блокирует адрес, успешный вход счётчик сбрасывает
- [x] подделка `X-Forwarded-For`/`X-Real-IP` с нелокального адреса блокировку не обходит
- [x] cookie `HttpOnly`, `Secure`, `SameSite=Lax`, с продлением
- [x] запрос без сессии к любому пути под `/api/`, кроме входа, даёт `401`
- [x] паника в обработчике не роняет демон и попадает в лог со стеком
- [x] тесты на `httptest`, без сети и root; `go vet`, `go test`, `gofmt` чисты
