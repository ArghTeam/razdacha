## TLDR

Кликабельный прототип панели в `ui/prototype/`: четыре экрана из
[docs/06-ui-screens.md](../docs/06-ui-screens.md) на HTML + CSS + ванильном JS,
без сборки и без внешних ресурсов. Данные — моки в формах `docs/05-api.md`.
Это макет для обсуждения, не заготовка продакшн-кода: настоящий интерфейс будет
на SvelteKit.

## Goal

Увидеть и раскритиковать интерфейс до того, как под него написан хоть один
Go-хендлер. Прототип отвечает на вопросы, которые текстовое описание экранов
оставляет открытыми: видно ли, что правила проверяются по порядку; хватает ли
одного поля для добавления туннеля; помещается ли всё это на телефон.

Побочная цель — сверить экраны с моделью данных и выписать места, где UI просит
поле, которого нет ни в БД, ни в производных.

## Domains touched

- [ui](../context/ui/index.md) — четыре экрана, дефолты вместо опций

## Decisions

- 2026-07-25 — ванильный JS вместо SvelteKit: прототип нужен, чтобы на него
  посмотреть, а не чтобы из него вырос продакшн. Node в окружении не поднимается
  из неинтерактивного shell, а прототип на голом HTML открывается любым
  `python3 -m http.server`.
- 2026-07-25 — QR-код кодируется своим генератором (byte mode, уровень L,
  версии 1–40) прямо в `app.js`, а не библиотекой с CDN: панель едет в бинарник
  через `go:embed`, внешним ресурсам там взяться неоткуда. Кодер сверен с
  `qrencode`: при одинаковой маске матрицы совпадают побитово, плюс проверен
  обратный проход (матрица → текст).
- 2026-07-25 — приоритет правил переставляется кнопками «вверх/вниз», не
  перетаскиванием: drag-and-drop на ванили — это ощутимый объём кода ради
  жеста, который в макете ничего не проверяет. В продакшне остаётся `⠿`.
- 2026-07-25 — правило, перекрытое вышестоящим по общему списку или домену,
  подсвечивается прямо в строке («перекрыто правилом …»). Порядок проверки —
  единственная концепция, которую пользователь обязан понять; подписи в шапке
  для этого мало, нужен пример на своих же данных.
- 2026-07-25 — разбор вставленного конфига туннеля повторён на клиенте
  урезанной копией `POST /api/tunnels/parse`. В проде разбирает демон; здесь
  копия нужна, чтобы форма вела себя как настоящая, включая превью до
  сохранения.
- 2026-07-25 — экранов ровно четыре, настройки — иконка в шапке с пятью полями,
  как в описании. Ничего сверх описанного не добавлено намеренно: прототип
  проверяет заявленный объём, а не расширяет его.

## Acceptance criteria

- [x] четыре экрана переключаются без перезагрузки, состояние в адресной строке
      (`#peers`, `#tunnels`, `#rules`, `#diag`)
- [x] ни одного внешнего запроса: ни CDN, ни шрифтов, ни картинок
- [x] порядок правил виден номером и меняется кнопками, приоритет остаётся
      плотным 0..n-1
- [x] пир online/offline считается по правилу «хендшейк < 3 минут»
- [x] туннель показывает up/down и задержку в мс
- [x] добавление туннеля — одно поле, тип определяется разбором, результат
      показан до сохранения
- [x] конфиг клиента отдаётся QR-кодом и файлом `.conf`; в конфиге всегда
      `DNS`, `MTU`, `AllowedIPs = 0.0.0.0/0, ::/0`, `PersistentKeepalive = 25`
- [x] тёмная и светлая темы через `prefers-color-scheme`
- [x] на ширине 500 px нет горизонтальной прокрутки
- [x] отчёт диагностики маскирует ключи и внешние адреса
