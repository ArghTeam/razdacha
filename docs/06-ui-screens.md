# Экраны UI

Четыре экрана. Любая новая настройка должна либо вытеснить существующую, либо быть
отклонена — см. [принципы](00-vision.md#ключевые-продуктовые-принципы).

Стек: статика без сборщика — HTML, CSS и ES-модули в `ui/dist`, встраивается в бинарник
демона через `go:embed`. Тёмная тема по системной настройке. Почему не Svelte + Vite —
в [спеке задачи #22](../tasks/22-ui.md#decisions).

## 1. Клиенты

Главный экран, открывается по умолчанию — самая частая задача — «добавить устройство».

```
┌──────────────────────────────────────────────────────────────┐
│  Клиенты                                    [+ Добавить]     │
├──────────────────────────────────────────────────────────────┤
│  ● iPhone Ромы      10.8.0.5    ↓ 184 МБ ↑ 12 МБ    [QR] [⋮] │
│  ● MacBook          10.8.0.6    ↓ 2.1 ГБ ↑ 340 МБ   [QR] [⋮] │
│  ○ Телевизор        10.8.0.7    был 3 дня назад     [QR] [⋮] │
└──────────────────────────────────────────────────────────────┘
```

- `●` / `○` — хендшейк менее / более 3 минут назад
- `[+ Добавить]` → спрашивает только имя → сразу открывает модальное окно с QR-кодом
  и кнопкой «Скачать .conf». Никаких настроек: адрес, ключи, MTU, DNS выставляются сами
- `[⋮]` — переименовать, отключить, удалить
- Трафик — накопительно с момента создания пира

**Осознанно отсутствует:** выбор адреса, срок действия, лимиты трафика, выбор правил
для пира (это на экране «Правила», со стороны правила).

## 2. Туннели

```
┌──────────────────────────────────────────────────────────────┐
│  Туннели                                    [+ Добавить]     │
├──────────────────────────────────────────────────────────────┤
│  ● Нидерланды       vless    nl.example.com     42 мс   [⋮]  │
│  ● Домашний wg      wireguard  198.51.100.7     18 мс   [⋮]  │
│  ⚠ Резервный        hysteria2  hy.example.net   нет ответа   │
└──────────────────────────────────────────────────────────────┘
```

Добавление — одно поле `textarea` и имя:

```
┌─ Новый туннель ──────────────────────────────────────────────┐
│  Имя:  [ Нидерланды                                       ]  │
│                                                              │
│  Вставьте ссылку или конфиг WireGuard:                       │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ vless://uuid@nl.example.com:443?security=reality&...    │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ✓ Распознан VLESS · REALITY · TCP · nl.example.com:443      │
│                                             [Отмена] [Сохранить] │
└──────────────────────────────────────────────────────────────┘
```

Разбор идёт по мере ввода (`POST /api/tunnels/parse`), результат показывается строкой
подтверждения или внятной ошибкой. Пользователь видит, что вставил, **до** сохранения —
это снимает основной класс обращений в поддержку.

Поддерживаются: `vless://`, `ss://`, `trojan://`, `hysteria2://`, `hy2://`, `socks5://`,
INI-конфиг WireGuard, произвольный JSON outbound.

## 3. Правила

```
┌──────────────────────────────────────────────────────────────┐
│  Правила                                    [+ Добавить]     │
│  Проверяются сверху вниз, первое совпадение выигрывает.      │
├──────────────────────────────────────────────────────────────┤
│  ⠿  1  Банки и госуслуги    → напрямую          вкл  [⋮]     │
│  ⠿  2  YouTube и Google     → Нидерланды        вкл  [⋮]     │
│  ⠿  3  Соцсети              → Нидерланды        вкл  [⋮]     │
│  ⠿  4  Реклама              → блокировать       выкл [⋮]     │
└──────────────────────────────────────────────────────────────┘
```

`⠿` — перетаскивание. Подпись про порядок проверки стоит прямо в шапке: это единственная
концепция, которую пользователь обязан понять, и её нельзя спрятать.

Редактирование правила:

```
┌─ YouTube и Google ─────────────────────────────────────────────────────┐
│  Правила проверяются сверху вниз, побеждает первое совпавшее. Это 2-е…  │
├─ ЧТО ЗА ПРАВИЛО ─────────────────┬─ НА ЧТО РАСПРОСТРАНЯЕТСЯ ───────────┤
│  Название: [ YouTube и Google  ] │  ▾ Готовые списки · выбрано 2       │
│  Куда: ( ) напрямую              │  [ поиск: youtube, telegram…      ] │
│        (•) в туннель [Нидерл. ▾] │  (YouTube ✕) (Google ✕)             │
│        ( ) блокировать           │  ┌─────────────────────────────┐    │
│  Свои домены:                    │  │ [✓] YouTube   [✓] Google    │ ▲  │
│  ┌────────────────────────────┐  │  │ [ ] Meta      [ ] Twitter   │ ▼  │
│  │ example.com                │  │  │ [ ] Telegram  [ ] Discord   │    │
│  └────────────────────────────┘  │  └─────────────────────────────┘    │
│  Свои подсети:                   │  Для кого: (•) все ( ) выбранные    │
│  ┌────────────────────────────┐  │                                     │
│  │ 203.0.113.0/24             │  │                                     │
│  └────────────────────────────┘  │                                     │
├──────────────────────────────────┴─────────────────────────────────────┤
│  ⚠ Это уже забирают правила выше: «Банки и госуслуги» — Cloudflare      │
│                                                    [Отмена] [Сохранить] │
└────────────────────────────────────────────────────────────────────────┘
```

Две зоны, а не список полей: слева — чем правило является, справа — на что оно
распространяется. Высота окна задана, а не набрана содержимым: прокручивается каталог
внутри своей зоны, поэтому ни число выбранных списков, ни длина списка доменов габаритов
окна не меняют. На узком экране колонки схлопываются в одну, каталог сворачивается в
строку со счётчиком выбранного.

Валидация доменов и подсетей — по мере ввода, построчно, с подсветкой некорректных строк.
Валидаторы портируются из `fe-app-podkop/src/validators/` вместе с тестами.

## 4. Диагностика

```
┌──────────────────────────────────────────────────────────────┐
│  Диагностика                        [Проверить заново]       │
├──────────────────────────────────────────────────────────────┤
│  ✓  WireGuard        wg0 поднят, 3 пира, 2 онлайн            │
│  ✓  sing-box         1.12.4, запущен 4 часа назад            │
│  ✓  Правила nftables таблица razdacha, 1284 подсети          │
│  ⚠  Туннели          «Резервный» не отвечает                 │
│  ✓  Списки           обновлены 3 часа назад                  │
│  ✓  IP forwarding    включён                                 │
│  ✓  Path MTU         1500 до всех туннелей                   │
├──────────────────────────────────────────────────────────────┤
│  [Скачать отчёт]   [Логи]   [Конфиг sing-box]                │
└──────────────────────────────────────────────────────────────┘
```

«Скачать отчёт» собирает всё в один текстовый файл для багрепорта — с замаскированными
ключами, IP-адресами эндпоинтов и UUID. Маскирование обязательно: пользователи вставляют
такие отчёты в публичные чаты. Функция `maskIP` берётся из `fe-app-podkop/src/helpers/`.

## Общие элементы

**Плашка непримененных изменений** — фиксирована внизу, появляется после правки правил
или настроек:

```
  Есть непримененные изменения                    [Применить]
```

Причина отложенного применения — в [API](05-api.md#applying).

**Настройки** — не отдельный пункт навигации, а иконка шестерёнки в шапке. Модальное
окно с пятью полями: порт WireGuard, внешний адрес, MTU клиентов, DNS, частота
обновления списков. Всё прочее живёт в `config.yaml`.

## Что не делаем

- Графики трафика по каждому пиру с историей — суммарный график на экране клиентов
  достаточен, хранение временных рядов тянет за собой отдельную подсистему.
- Редактор JSON-конфига sing-box в UI — только просмотр. Кто умеет править — правит
  через `raw` туннеля.
- Мастер первичной настройки. Установщик доводит систему до рабочего состояния сам,
  визарду нечего спрашивать.
