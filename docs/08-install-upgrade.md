# Установка, обновление, удаление

## Установка

```sh
curl -fsSL https://razdacha.example/install.sh | sh
```

Порядок шагов — важен именно такой, «сначала все проверки, потом все изменения»:

**Фаза 1 — проверки, система не трогается**
1. root, systemd, ядро ≥ 5.15, архитектура из поддерживаемых
2. дистрибутив из [матрицы](07-platform-support.md#матрица)
3. `systemd-detect-virt` — отказ на OpenVZ
4. `modprobe wireguard nft_tproxy nft_socket`, наличие `/dev/net/tun`
5. свободное место ≥ 100 МБ
6. конфликты: `wg0`, `wg-quick@wg0`, чужой `/etc/sing-box/config.json`
7. определение внешнего адреса и WAN-интерфейса

**Фаза 2 — изменения**
8. установка `sing-box` (пакет из репозитория, иначе бинарник в `/usr/local/bin`)
9. установка `razdacha.deb`
10. `net.ipv4.ip_forward=1` → `/etc/sysctl.d/99-razdacha.conf`
11. генерация ключей сервера, `config.yaml`, инициализация БД
12. поднятие `wg0`, заливка nft-правил, первичный конфиг sing-box
13. `systemctl enable --now razdachad sing-box`
14. создание первого пира с именем по hostname клиента или `client-1`

**Фаза 3 — вывод**
```
  Готово.

  Отсканируйте QR-код клиентом WireGuard:

    ███████████████████████
    ██ ▄▄▄▄▄ █▀▄█ ▄▄▄▄▄ ███
    …

  Или скачайте конфиг:  /var/lib/razdacha/client-1.conf

  После подключения интерфейс будет доступен по адресу:
    http://10.8.0.1:8080

  Не забудьте открыть UDP-порт 51820 в файрволе провайдера.
```

Последняя строка обязательна: у большинства облачных провайдеров есть внешняя группа
безопасности, о которой мы ничего не знаем. Это самая частая причина «установил, но не
подключается».

## Почему UI недоступен до подключения

Интерфейс слушает только на `10.8.0.1` — попасть на него можно исключительно из VPN
([модель привилегий](01-architecture.md#модель-привилегий)). Отсюда порядок: установщик
создаёт первого пира и печатает конфиг сам, иначе система была бы недоступна для
настройки.

Альтернатива для тех, кто ставит без физического доступа к терминалу:
`install.sh --listen-public --password <pass>` — UI слушает `0.0.0.0:8080` с обязательным
паролем и самоподписанным TLS. Не дефолт и в документации подаётся как компромисс.

## Идемпотентность

Повторный запуск `install.sh` на настроенной системе выполняет обновление, а не
переустановку: ключи сервера, пиры, туннели и правила сохраняются. Проверка — наличие
`/var/lib/razdacha/state.db`.

## Обновление

```sh
razdacha update      # или тот же install.sh
```

1. проверка новой версии на GitHub Releases
2. скачивание `.deb` для текущей архитектуры
3. `systemctl stop razdachad`
4. **резервная копия БД** в `/var/lib/razdacha/backups/state-<version>.db`
5. установка пакета, миграции схемы при старте
6. `systemctl start razdachad`, регенерация конфига sing-box
7. проверка: демон отвечает, `wg0` поднят, пиры на месте

При падении миграции — откат на резервную копию и сообщение с путём к ней.

**Клиентские конфиги при обновлении не меняются** — ключи, адреса и порт сохраняются.
Исключение — смена `client_mtu` или `wg_pool` в новой версии; такие изменения требуют
явного действия пользователя и не применяются автоматически.

## Systemd-юнит

```ini
[Unit]
Description=razdacha selective VPN gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=notify
ExecStart=/usr/bin/razdachad
Restart=on-failure
RestartSec=5

NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/razdacha /etc/razdacha /etc/sing-box
PrivateTmp=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_NETLINK AF_UNIX
CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_RAW CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target
```

`Type=notify` — демон сообщает о готовности после того, как `wg0` поднят и nft-правила
залиты, а не сразу при старте процесса.

`sing-box` управляется своим штатным юнитом; razdachad делает `systemctl reload sing-box`
после регенерации конфига.

## Удаление

```sh
razdacha uninstall
```

Восстанавливает исходное состояние системы:

1. остановка и отключение юнитов
2. удаление `wg0`
3. удаление таблицы `inet razdacha`, `ip rule` и таблицы маршрутизации 105
4. удаление `/etc/sysctl.d/99-razdacha.conf` и перечитывание sysctl
5. `apt remove razdacha`
6. спрашивает отдельно: удалять ли `/var/lib/razdacha` (пиры и ключи) и `sing-box`

Podkop показывает, почему это важно: там неполная очистка (остатки в
`/etc/iproute2/rt_tables`, изменённый `/etc/config/dhcp`) — постоянный источник проблем
при переустановке. Все системные изменения должны быть перечислены и обратимы; тест на
чистое удаление — часть CI.

## Ручное восстановление

Если демон не стартует, интернет у клиентов не должен пропадать полностью. Прямой путь
(masquerade) не зависит от sing-box, а nft-правила остаются в ядре после остановки
демона — теряется только селективность. Для полного сброса:

```sh
razdachad --reset-network     # снять nft-правила, ip rule, маршруты; wg0 оставить
```
