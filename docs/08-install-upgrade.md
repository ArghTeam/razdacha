# Установка, обновление, удаление

## Установка

```sh
curl -fsSL https://razdacha.example/install.sh | sh
```

Порядок шагов — важен именно такой, «сначала все проверки, потом все изменения»:

**Фаза 1 — проверки, система не трогается**
1. root, systemd, ядро ≥ 5.15, архитектура из поддерживаемых
2. дистрибутив из [матрицы](07-platform-support.md#матрица)
3. `systemd-detect-virt` — отказ на OpenVZ
4. `modprobe wireguard nft_tproxy nft_socket`, наличие `/dev/net/tun`
5. свободное место ≥ 100 МБ
6. конфликты: `wg0`, `wg-quick@wg0`, чужой `/etc/sing-box/config.json`,
   чужой `/etc/nginx/sites-available/razdacha` (файл без нашего заголовка-маркера)
7. определение внешнего адреса и WAN-интерфейса

**Фаза 2 — изменения**
8. установка `sing-box` (пакет из репозитория, иначе бинарник в `/usr/local/bin`)
9. установка `nginx`, если его нет: `apt-get install -y nginx`
10. установка `razdacha.deb`
11. `net.ipv4.ip_forward=1` и `net.ipv4.ip_nonlocal_bind=1` →
    `/etc/sysctl.d/99-razdacha.conf`
12. генерация ключей сервера, `config.yaml`, инициализация БД
13. сертификат панели в `/etc/razdacha/tls/` (см. ниже) и конфиг nginx
    в `/etc/nginx/sites-available/razdacha` + symlink в `sites-enabled`
14. поднятие `wg0`, заливка nft-правил, первичный конфиг sing-box
15. `systemctl enable --now razdachad sing-box`, `systemctl reload nginx`
16. создание первого пира с именем по hostname клиента или `client-1`

**Фаза 3 — вывод**
```
  Готово.

  Отсканируйте QR-код клиентом WireGuard:

    ███████████████████████
    ██ ▄▄▄▄▄ █▀▄█ ▄▄▄▄▄ ███
    …

  Или скачайте конфиг:  /var/lib/razdacha/client-1.conf

  После подключения интерфейс будет доступен по адресу:
    https://10.8.0.1

  Сертификат самоподписанный — браузер предупредит при первом заходе.

  Не забудьте открыть UDP-порт 51820 в файрволе провайдера.
```

Последняя строка обязательна: у большинства облачных провайдеров есть внешняя группа
безопасности, о которой мы ничего не знаем. Это самая частая причина «установил, но не
подключается».

## nginx и сертификат

Панель стоит за nginx ([ADR 0008](decisions/0008-nginx-before-panel.md)). Установщик
делает с ним ровно три вещи:

1. **Сертификат.** Если `/etc/razdacha/tls/cert.pem` уже есть, разбирается, не просрочен
   и содержит **все** нужные IP в SAN — он остаётся как есть. Иначе генерируется новый:
   ECDSA P-256 средствами Go (не вызовом `openssl` — внешние бинарники мы не дёргаем),
   срок 10 лет. Каталог `0700`, ключ `0600`, сертификат `0644`.
   Перевыпускать самоподписанный сертификат по расписанию нечем и незачем, отсюда срок.

   SAN — `10.8.0.1`, а в публичном режиме ещё и внешний адрес сервера: при заходе по
   публичному IP без него браузер ругается на несовпадение имени, а это предупреждение
   страшнее и непонятнее, чем «неизвестный издатель». «Все нужные IP» здесь и есть
   условие перевыпуска при переходе в публичный режим: у выпущенного сертификата SAN
   сам не вырастет. Внешний адрес берётся из маршрутизации — UDP-сокет до публичного
   адреса без единого отправленного пакета показывает, каким адресом машина выходит
   наружу; ни root, ни интернет, ни сторонняя служба вроде `ifconfig.me` не нужны. Если
   адрес определить не удалось, установка не падает: сертификат выпускается на один
   `10.8.0.1`, а причина уходит в лог.
2. **Конфиг.** `/etc/nginx/sites-available/razdacha` генерируется кодом из настроек:
   адрес `wg0`, порты, пути к сертификату и ключу, адрес демона — подставляются, а не
   зашиты в файл-шаблон. Первая строка — заголовок-маркер `# razdacha: …`. Файл на этом
   пути без маркера считается чужим: установка останавливается с ошибкой и ничего не
   перезаписывает.
3. **Symlink.** `/etc/nginx/sites-enabled/razdacha` → на файл выше. Если по этому пути
   уже лежит symlink на наш файл — ничего не делается. Если что-то другое — ошибка.
4. **Снимает дефолтный сайт Debian** — `/etc/nginx/sites-enabled/default`. Пакет nginx
   включает его сам, а слушает он `listen 80 default_server` и `listen [::]:80
   default_server`, то есть `0.0.0.0:80` и `[::]:80` на публичном интерфейсе. Пока он
   включён, панель видна из интернета мимо нашего конфига: наш файл при этом безупречен,
   дыру создаёт чужой. Symlink снимается только если ведёт на `sites-available/default`;
   сам файл в `sites-available` не трогается, он принадлежит пакету. Факт снятия
   записывается в `/etc/razdacha/nginx-default-disabled.json`, и по этой отметке сайт
   возвращается при удалении. Symlink с именем `default`, ведущий куда-то ещё, — чужая
   настройка: не трогается, о чём пишется в лог.

Ничего другого в `/etc/nginx` не трогается: ни `nginx.conf`, ни файлы в
`sites-available`, ни чужие сайты.

## Почему nginx не стартует без `ip_nonlocal_bind`

nginx привязан к `10.8.0.1`, а этот адрес появляется вместе с `wg0`, который создаёт
демон. После перезагрузки nginx стартует раньше и падает с «cannot assign requested
address» — юнит уходит в `failed`, панель недоступна до ручного рестарта.

Лечится `net.ipv4.ip_nonlocal_bind=1` в том же `/etc/sysctl.d/99-razdacha.conf`:
процессу разрешается слушать адрес, которого ещё нет. Установщик пишет параметр в drop-in
(чтобы он пережил перезагрузку) и сразу проставляет его в `/proc/sys` (чтобы не ждать её).

Порядок юнитов через `After=` эту задачу не решает: `razdachad` может уже стартовать, а
`wg0` — ещё не подняться, и nginx снова не найдёт адрес.

**Если nginx не установлен**, установщик ставит его через `apt-get install -y nginx`.
Код настройки при отсутствии `/etc/nginx/sites-available` не падает с невнятной ошибкой
файловой системы, а сообщает: `nginx не установлен: каталог … не найден; установите
пакет: apt install nginx`.

## Режимы доступа к панели

По умолчанию nginx слушает только `10.8.0.1` — попасть на панель можно исключительно из
VPN ([модель привилегий](01-architecture.md#модель-привилегий)). Отсюда порядок:
установщик создаёт первого пира и печатает конфиг сам, иначе система была бы недоступна
для настройки.

В публичном режиме ([ADR 0009](decisions/0009-public-panel-access.md)) nginx слушает
`443` и `80` на всех интерфейсах; отдельного `listen` на `10.8.0.1` не нужно — он уже
покрыт, и изнутри VPN панель открывается как раньше. Вход прикрыт `limit_req` на
`POST /api/login`: зона `razdacha_login` на `$binary_remote_addr`, `10r/m` при всплеске
в 5 запросов, при превышении — `429`. Это заведомо выше живого человека с опечатками и
заведомо ниже перебора; точная защита — блокировка по адресу в самом демоне. Ограничение
висит только на входе: на `/` оно ломало бы панель, один экран тянет десятки запросов.

Режим — явный флаг, а не следствие настройки адреса: без него адрес вне приватного
диапазона и `0.0.0.0` по-прежнему отвергаются до генерации конфига. Демон в обоих
режимах сидит на `127.0.0.1:8080` и не виден даже из VPN.

## Идемпотентность

Повторный запуск `install.sh` на настроенной системе выполняет обновление, а не
переустановку: ключи сервера, пиры, туннели и правила сохраняются. Проверка — наличие
`/var/lib/razdacha/state.db`.

То же и для nginx: конфиг переписывается, только если его содержимое отличается от
сгенерированного; symlink не дублируется; валидный сертификат не перевыпускается.

## Обновление

```sh
razdacha update      # или тот же install.sh
```

1. проверка новой версии на GitHub Releases
2. скачивание `.deb` для текущей архитектуры
3. `systemctl stop razdachad`
4. **резервная копия БД** в `/var/lib/razdacha/backups/state-<version>.db`
5. установка пакета, миграции схемы при старте
6. `systemctl start razdachad`, регенерация конфига sing-box и конфига nginx
7. проверка: демон отвечает, `wg0` поднят, пиры на месте

Конфиг nginx на обновлении пересобирается тем же кодом и переписывается, только если
изменился; сертификат, если он валиден, не перевыпускается — иначе у пользователя каждый
раз слетало бы исключение, добавленное в браузере.

При падении миграции — откат на резервную копию и сообщение с путём к ней.

**Клиентские конфиги при обновлении не меняются** — ключи, адреса и порт сохраняются.
Исключение — смена `client_mtu` или `wg_pool` в новой версии; такие изменения требуют
явного действия пользователя и не применяются автоматически.

## Systemd-юнит

```ini
[Unit]
Description=razdacha selective VPN gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=notify
ExecStart=/usr/bin/razdachad
Restart=on-failure
RestartSec=5

NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/razdacha /etc/razdacha /etc/sing-box
PrivateTmp=yes
RestrictAddressFamilies=AF_INET AF_INET6 AF_NETLINK AF_UNIX
CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_RAW CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target
```

`Type=notify` — демон сообщает о готовности после того, как `wg0` поднят и nft-правила
залиты, а не сразу при старте процесса.

`sing-box` управляется своим штатным юнитом; razdachad делает `systemctl reload sing-box`
после регенерации конфига.

## Удаление

```sh
razdacha uninstall
```

Восстанавливает исходное состояние системы:

1. остановка и отключение юнитов
2. удаление `wg0`
3. удаление таблицы `inet razdacha`, `ip rule` и таблицы маршрутизации 105
4. удаление `/etc/sysctl.d/99-razdacha.conf` и перечитывание sysctl
5. снятие symlink `/etc/nginx/sites-enabled/razdacha` и файла
   `/etc/nginx/sites-available/razdacha`, возврат дефолтного сайта Debian, если снимали
   его мы, затем `systemctl reload nginx`
6. `apt remove razdacha`
7. спрашивает отдельно: удалять ли `/var/lib/razdacha` (пиры и ключи) и `sing-box`

Шаг 5 избирателен: symlink снимается, только если он ведёт на наш файл, а файл удаляется,
только если в нём есть заголовок-маркер. Чужой конфиг с тем же именем остаётся на месте.
Дефолтный сайт возвращается только при наличии отметки `/etc/razdacha/nginx-default-disabled.json`
— если пользователь выключил его сам, удаление razdacha не включит его обратно.
Сам nginx не удаляется — его могли поставить до нас и использовать для другого.
Сертификат лежит в `/etc/razdacha/tls/` и уходит вместе с `/etc/razdacha`.

Podkop показывает, почему это важно: там неполная очистка (остатки в
`/etc/iproute2/rt_tables`, изменённый `/etc/config/dhcp`) — постоянный источник проблем
при переустановке. Все системные изменения должны быть перечислены и обратимы; тест на
чистое удаление — часть CI.

## Ручное восстановление

Если демон не стартует, интернет у клиентов не должен пропадать полностью. Прямой путь
(masquerade) не зависит от sing-box, а nft-правила остаются в ядре после остановки
демона — теряется только селективность. Для полного сброса:

```sh
razdachad --reset-network     # снять nft-правила, ip rule, маршруты; wg0 оставить
```
