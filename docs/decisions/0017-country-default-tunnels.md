# 0017. Дефолтные туннели — по одному пулу на захардкоженную страну

Дата: 2026-08-17 · Статус: заменено [0018](0018-unified-pool.md) (возврат к единому пулу без geo-IP)

## Контекст

[ADR 0015](0015-pool-source-driver.md) оставил встроенный пул единственным: «пул в
системе один и его заводит демон» (`EnsureBuiltinPool`). Один пул означает один выход
наугад — какая страна попадётся в `urltest`, та и работает, и пользователь на это не
влияет. Источник (outlinekeys) к тому же ненадёжен: из собранного реально проксирует
около четверти, все выходы — дата-центры.

Владелец захотел выбор выхода по стране, с той же ротацией внутри, что уже даёт пул.
[ADR 0010](0010-tunnel-pool-urltest.md) это прямо предвидел: «`selector` пригодится,
когда пользователь захочет прибить туннель к конкретной стране».

Разведка нового источника `igareck/vpn-configs-for-russia` на стенде 2026-08-17 (три
plain-text подписки, адреса резолвились и геолоцировались офлайн-базой DB-IP Country
Lite, релиз 2026-08; прокси-проб не было): 800 ключей, **258 уникальных exit-IP**.
Числа важны дедупом — по ключам страна бывает «жирной» обманчиво (NZ: 58 ключей на 3 IP).

| страна | уникальных exit-IP |
|---|---|
| NL | 38 |
| DE | 35 |
| RU | 22 |
| US | 20 |
| FR | 14 |
| GB | 12 |
| PL / LV / KZ | по 10 |
| FI | 8 |
| хвост (TW, JP, SE, …) | ≤8, много по 1 |

Порог отбора — двузначное число уникальных IP: пулу с `urltest` нужна горстка живых
выходов, из которых есть что ротировать, а пул из трёх адресов — это видимость туннеля,
не туннель. RU отброшен отдельно: выходить в России в сервисе для обхода России
бессмысленно. KZ включён при 10 IP осознанно — сосед по латентности; PL и LV той же
толщины оставлены на потом, набор задаётся одним местом в коде.

Механику проверять не пришлось: `singbox.buildPool` парсит каждую ссылку по отдельности
(`internal/singbox/pool.go:145`), тип outbound берётся из ссылки, а не из `tunnel.Type`.
Смешанный по протоколам пул (vless + shadowsocks + trojan из одной страны) собирается
без изменений слоя singbox.

## Решение

**Дефолтных туннелей — по одному встроенному пулу на захардкоженную страну.** Набор:
🇳🇱 NL, 🇩🇪 DE, 🇺🇸 US, 🇫🇷 FR, 🇬🇧 GB, 🇫🇮 FI, 🇰🇿 KZ — семь пулов. Каждый снаружи
остаётся одним туннелем с одним `urltest` под тегом `TunnelTag(id)` (ADR 0010): выбор
страны — это выбор туннеля в правиле, модель правил не меняется. Единственный встроенный
пул из ADR 0015 упраздняется: `EnsureBuiltinPool` уступает место
`EnsureBuiltinCountryPools`, старая запись удаляется миграцией, ссылавшиеся на неё
правила отвязываются (падают в `reject` по [ADR 0013](0013-unavailable-tunnel-rejects.md)
или выключаются — с записью в лог, молча не удаляются).

**Страна сервера определяется офлайн geo-IP базой по его адресу, а не меткой источника.**
База (DB-IP Country Lite, mmdb) уезжает в бинарник через `go:embed` и читается чистым Go
(`maxminddb`, без CGO — инвариант `CGO_ENABLED=0` цел). Адрес сервера уже лежит в ссылке;
домен резолвится, IP отдаёт страну. Метку из URL или фрагмента мы не берём принципиально:
[issue #161](https://github.com/ArghTeam/razdacha/issues/161) закрыт доказательством, что
метки врут.

**Источник один на все семь пулов, обход тоже один.** Подписки igareck тянутся один раз,
ключи геолоцируются и раскладываются по странам, каждый пул получает свой срез
(fetch-once-partition). Ходить за одним и тем же файлом семь раз нельзя — и по вежливости
к источнику, и потому что дедуп обхода (`beginCrawl`) отдал бы ключи только первому пулу.
Основной адрес — зеркало на CDN, `raw.githubusercontent.com` — резерв: raw github у части
РФ-провайдеров режется, а именно там обход и должен работать.

**Всё выключено по умолчанию.** Семь пулов заводятся выключенными, наружу за ключами до
включения не ходит никто — как того требует конституция и как уже устроены пул и
оповещения. Обновление состава — существующее расписание `PoolManager` (12 часов),
нового systemd-таймера не появляется.

## Последствия

**Положительные**
- Выход выбирается по стране, а ротация на живой-быстрый внутри страны остаётся
  бесплатной (ADR 0010): смена сервера не трогает конфиг и соседние туннели.
- Наполнение честнее прежнего: доля реально проксирующих у igareck ~85–90 % против
  четверти у outlinekeys, и в пул попадают только серверы своей страны, проверенной
  нами, а не заявленной источником.
- Один обход на семь пулов — нагрузка на источник не растёт всемеро.

**Отрицательные**
- Конфиг распухает кратно числу включённых стран: семь включённых пулов — это до
  7×(16+1) записей в `outbounds[]` и семь групп `urltest`. Смягчено тем, что по
  умолчанию включённых нет.
- Бинарник тяжелеет на ~4 МБ — встроенная mmdb. Плата за отсутствие сети при определении
  страны.
- База geo-IP заморожена на релизе и обновляется только с обновлением razdacha. Для
  дата-центровых IP страна меняется редко, но расхождение возможно, и это не ошибка, а
  свойство.
- DB-IP Country Lite под **CC-BY-4.0**: атрибуция обязана уехать в бинарник и доки. Забыть
  её — нарушить лицензию.
- Набор стран прошит в коде: чтобы добавить PL или убрать KZ, нужен релиз, а не настройка.
  Осознанно — набор про запас ключей источника, а не про вкус пользователя.
- Смешанный по протоколам пул усложняет диагностику: «туннель KZ работает» значит
  «работает хотя бы один из его vless/ss/trojan-участников».

## Альтернативы

**Оставить один пул, добавить в панель выбор страны фильтром.** Дешевле в коде, но выбор
остался бы косметикой: `urltest` всё равно гоняет всю группу и уводит трафик куда быстрее,
без гарантии страны. Прибить выход к стране можно только отдельной группой на страну.

**Страну брать из метки источника (имя ключа, `#fragment`).** Бесплатно и без базы.
Отвергнуто: метки врут — ровно это доказал и закрыл issue #161 в тот же период. Пул,
набранный по вранью, — это не туннель нужной страны, а видимость.

**Онлайн geo-IP (запрос к API по каждому адресу).** База не нужна, всегда свежо.
Отвергнуто: сеть в момент наполнения, зависимость от чужого сервиса и утечка адресов
наших ключей наружу. Адрес и так лежит в ссылке — определять страну надо офлайн.

**Свой набор стран как настройка, а не хардкод.** Гибко. Отвергнуто на старте: набор
осмыслен только там, где у источника есть запас ключей, и меняется он со сменой источника,
а не по вкусу. Хардкод в одном месте кода — не преграда добавить страну позже.

## Источник в Podkop

Podkop умеет `urltest`-группу (`podkop/files/usr/bin/podkop:681`), но ссылки в неё
пользователь вписывает руками (`urltest_proxy_links`, там же:685). Ни каталога ключей, ни
их источника, ни определения страны у Podkop нет — «откуда взять ключ» и «какой он страны»
он не решает вовсе. Пул был нашим добавлением с самого начала (ADR 0010), а разбивка по
странам — его продолжением; аналога в оригинале нет.
