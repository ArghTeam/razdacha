# 0011. Состояние туннелей снимается по расписанию и хранится без задержки

Дата: 2026-07-27 · Статус: принято · Уточняет [0010](0010-tunnel-pool-urltest.md)

## Контекст

Проверка туннеля до сих пор запускалась только нажатием «Проверить», а результат жил в
памяти демона. Комментарий в `internal/api/tunnels_check.go` объяснял, почему в БД он не
пишется: задержка живёт минуты, а после перезапуска демона — а с ним и sing-box — уже
ничего не значит.

Аргумент верен, но он про задержку, а не про состояние. На практике это давало экран
туннелей, который при каждом заходе показывает «не проверялось» по всем строкам, даже
если туннели работают месяц. Пустота, которая по конвенции означает «никто не проверял»
(`docs/05-api.md`, `docs/06-ui-screens.md`), оказалась нормой вместо исключения.

Второе обстоятельство — цена активной пробы. `GET /proxies/{tag}/delay` заставляет
sing-box сходить до тестового URL через указанный прокси. Для обычного outbound'а это
один запрос. Но за тегом пула стоит группа `urltest` (решение 0010), и проба группы
означает прогон по всем её участникам — то есть по сотне серверов из каталога, на каждом
круге расписания. При этом ровно эту работу sing-box уже делает сам: `urltest` опрашивает
участников по своему расписанию, и именно по её результату переключается трафик.

Инвариант слоя api это уже фиксировал для пула: своей проверялки не заводим, потому что
она расходилась бы с той, по которой реально идёт трафик.

## Решение

**Состояние снимается по расписанию**, интервал — настройка `tunnel_check_interval`,
по умолчанию две минуты. Меньше 30 секунд не принимается.

**Один запрос `/proxies` на круг вместо пробы каждого туннеля.** Для туннеля, за тегом
которого стоит группа, состояние берётся из журнала проверок sing-box — той самой, по
которой работает `urltest`. Активной пробой добираются только обычные outbound'ы: их не
проверяет никто, кроме нас.

**Пустой журнал группы — не «down».** Это значит, что sing-box ещё не успел её прогнать;
прежний результат со своей отметкой времени честнее выдуманного статуса. По той же
причине недоступный Clash API оставляет все прежние результаты нетронутыми.

**Хранится статус и время, задержка — нет.** Таблица `tunnel_checks`, отдельная от
`tunnels`: состояние проверки — наблюдение о туннеле, а не его часть, и в `Snapshot`,
откуда генерируется конфиг sing-box, ему делать нечего. Внешний ключ с `ON DELETE
CASCADE` — удалённый туннель не держит за собой запись.

## Последствия

Экран туннелей пуст ровно один раз — между стартом демона и первым прогоном, и то лишь
пока в БД нет сохранённых проверок. Конвенция «`null` = никто не проверял» не меняется,
но перестаёт быть тем, что пользователь видит по умолчанию.

Задержка по-прежнему не переживает перезапуск: после подъёма сохранённых проверок в
интерфейсе видно статус и время, а цифра появляется после первого прогона. Показывать
старую задержку рядом со старым временем значило бы врать точным числом.

Расписание даёт то, на чём стоит подтверждение переходов для уведомлений: без
регулярного прогона «три проверки подряд» не имеет смысла.
