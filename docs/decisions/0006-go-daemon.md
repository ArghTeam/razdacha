# 0006. Демон на Go с импортом sing-box/option

Дата: 2026-07-25 · Статус: принято

## Контекст

Podkop написан на `ash` + `jq`: 2770 строк основного скрипта плюс 1508 строк
конструирования JSON-конфига. Конфиг хранится в shell-переменной и на каждом шаге
прогоняется через `echo | jq` в подоболочке — десятки-сотни вызовов `jq` на одну
генерацию. Отсюда же чанкованные импорты списков (1000 записей на патч, 5000 на
`nft add element`) — прямое следствие этой архитектуры, а не требование задачи.

На OpenWrt выбор вынужден: место на флеше ограничено, рантайма нет. На Debian
ограничений нет.

## Решение

Демон на **Go**, статический бинарник, `CGO_ENABLED=0`.

Ключевые библиотеки:

| Задача | Библиотека |
|---|---|
| Конфиг sing-box | `github.com/sagernet/sing-box/option` |
| nftables | `github.com/google/nftables` |
| WireGuard | `golang.zx2c4.com/wireguard/wgctrl` |
| Маршруты и правила | `github.com/vishvananda/netlink` |
| Хранилище | `modernc.org/sqlite` (чистый Go) |

## Обоснование

**Импорт `sing-box/option`** — главная причина выбора именно Go. Конфиг собирается
типизированными структурами того же проекта, который его потом читает. Ошибки полей и
типов ловятся компилятором, а не в рантайме на роутере пользователя. Это устраняет
1508 строк Podkop целиком.

**Netlink вместо вызова бинарников.** `nft`, `ip` и `wg` не вызываются — работа идёт
напрямую через netlink. Следствия: не нужны userspace-утилиты определённых версий, нет
парсинга текстового вывода, правила заливаются атомарно, версия дистрибутива почти не
влияет на совместимость ([поддержка платформ](../07-platform-support.md)).

**Статический бинарник.** Нет зависимости от glibc, рантаймов и системного SQLite.
В `.deb` попадает один файл со встроенной SPA (`go:embed`). Кросс-компиляция под arm64
тривиальна.

## Последствия

**Положительные**

- Конфиг генерируется целиком из состояния БД типизированно, без строковых манипуляций.
- Нет проблемы производительности `jq`: чанкование списков не требуется.
- Один артефакт на архитектуру, минимальная матрица зависимостей.
- Тестируемость: генератор конфига — чистая функция «состояние → `option.Options`»,
  покрывается unit-тестами без сети и root.

**Отрицательные**

- Зависимость от внутреннего API `sing-box/option`, который может меняться между
  минорными версиями. Смягчение: пин версии в `go.mod`, тест «сгенерированный конфиг
  проходит `sing-box check`» в CI на каждой поддерживаемой версии sing-box.
- Порог входа для контрибьюторов выше, чем у shell-скрипта.
- Размер бинарника — десятки мегабайт против сотен килобайт скриптов. На сервере
  безразлично.

## Альтернативы

**Rust.** Рассматривался ради единого языка с Tauri, но десктопная оболочка не нужна
([ADR 0001](0001-gateway-not-desktop.md)), а переиспользование типов sing-box было бы
потеряно.

**Python.** Отклонён: рантайм в зависимостях, упаковка в `.deb` сложнее, типизации
конфига sing-box нет.

**Портирование shell-архитектуры Podkop.** Отклонено: воспроизводит худшую часть
исходника без единой причины, специфичной для Debian.

## Источник в Podkop

`podkop/files/usr/lib/sing_box_config_manager.sh` (1508 строк, ~40 функций `sing_box_cm_*`)
и `sing_box_config_facade.sh` (335) — то, что заменяется типизированными структурами.
Логика разбора proxy-URL из фасада (`:58`–`:270`) портируется по смыслу, с
`podkop/String-example.md` в роли тестового корпуса.
