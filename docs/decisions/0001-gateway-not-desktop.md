# 0001. Шлюз, а не десктопное приложение

Дата: 2026-07-25 · Статус: принято

## Контекст

При переносе модели Podkop на Debian/Ubuntu возможны два принципиально разных сценария:

**Десктоп.** Приложение на рабочей станции, трафик генерируется локально. Требует
перехвата локального трафика — на Linux это TUN-инбаунд sing-box с `auto_route`, плюс
исключение собственного трафика демона через cgroup или выделенный uid. Даёт
per-app маршрутизацию, невозможную на роутере.

**Шлюз.** Сервер принимает трафик клиентов и маршрутизирует его. Локальный трафик не
интересен, перехват — на форвардинге.

Выбор определяет всё остальное: способ перехвата, модель безопасности, форму UI,
целевого пользователя.

## Решение

Строим **шлюз**. Клиенты подключаются штатным WireGuard, сервер принимает их трафик на
`wg0` и маршрутизирует селективно.

## Последствия

**Положительные**

- Архитектура Podkop переносится почти дословно: `wg0` занимает место `br-lan`, вся
  механика tproxy + fwmark + FakeIP работает без изменений.
- Проблема перехвата DNS исчезает полностью. Podkop вынужден подменять конфигурацию
  dnsmasq с резервным копированием и восстановлением; мы задаём `DNS = 10.8.0.1` в
  клиентском конфиге и владеем резолвером с первого пакета. Не портируется ~150 строк
  самой хрупкой логики Podkop.
- Клиенту не нужно специальное ПО. Работает там, где sing-box не поставить: iOS без
  ухищрений, телевизоры, консоли.
- Не нужны cgroup-исключения и цепочка `mangle_output` — трафик самого сервера не
  обрабатывается.
- Один сервер обслуживает все устройства, включая мобильные вне дома.

**Отрицательные**

- Per-app маршрутизация невозможна: сервер видит только IP клиента, не приложение.
- Требуется сервер. Продукт не для тех, у кого его нет.
- Двойное шифрование: клиент↔сервер (WireGuard) и сервер↔апстрим (туннель). Накладные
  расходы на CPU сервера.
- Клиент полностью зависит от доступности сервера.

## Альтернативы

**Десктопное приложение с TUN.** Отклонено: рынок занят (clash-verge-rev, Hiddify,
FlClash), клиент требуется на каждом устройстве, мобильные платформы охватываются плохо.

**Оба сценария в одном продукте.** Отклонено: удваивает поверхность тестирования и
размывает UI, ради которого продукт и затевается.

## Источник в Podkop

Вся модель перехвата: `podkop/files/usr/bin/podkop:282` (`create_nft_rules`),
`:253` (`route_table_rule_mark`), `:796` (`sing_box_configure_route`).
Замена `source_network_interfaces = br-lan` (`podkop/files/etc/config/podkop`) на `wg0`.
