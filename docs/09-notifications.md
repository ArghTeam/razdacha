# Оповещения в телеграм

Демон умеет писать в телеграм. Бот принадлежит вам: своей регистрации у razdacha нет и
быть не может — токен выдаёт телеграм лично владельцу.

Транспорт один. Интерфейса «выберите способ оповещения» нет намеренно: абстракция под
второй транспорт до появления второго — догадка о том, каким он будет.

## 1. Завести бота

В телеграме напишите [@BotFather](https://t.me/BotFather):

```
/newbot
```

Он спросит имя и username (должен заканчиваться на `bot`) и ответит строкой вида
`8679364911:AAG…` — это **токен**. Он равносилен паролю: кто его получил, тот пишет от
имени бота.

## 2. Решить, куда писать

**В личку.** Напишите своему боту любое сообщение — без этого он не имеет права писать
вам первым. Затем откройте в браузере:

```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

В ответе найдите `"chat":{"id":123456789` — это ваш **chat_id**.

**В канал или группу.** Добавьте бота администратором с правом отправки сообщений.
Идентификатор канала с публичным username узнаётся так:

```
https://api.telegram.org/bot<ТОКЕН>/getChat?chat_id=@имя_канала
```

В ответе будет `"id":-1001234567890` — отрицательное число, это нормально: у каналов и
супергрупп идентификаторы отрицательные. Для приватного канала опубликуйте в него
сообщение и посмотрите `getUpdates`.

## 3. Включить

Два пути, оба пишут в одну и ту же запись в БД. Она и есть источник правды.

**Через панель.** Шестерёнка → блок «Оповещения в телеграм»: идентификатор чата, токен,
галочка «Присылать оповещения». Кнопка «Отправить тестовое» сохраняет введённое и сразу
пробует доставку — так видно, что не так, до того как что-нибудь случится.

**Через переменные окружения при установке.**

```sh
RAZDACHA_TELEGRAM_TOKEN=8679364911:AAG… \
RAZDACHA_TELEGRAM_CHAT=-1003795294413 \
  sh -c "$(curl -fsSL https://github.com/ArghTeam/razdacha/releases/latest/download/install.sh)"
```

Обе переменные заданы и непусты — оповещения записываются и включаются. Переменных нет —
в БД остаётся то, что было: обновление сервера не сбрасывает настроенное через панель.
`RAZDACHA_TELEGRAM_TOKEN=` (пустой) — оповещения выключаются, токен стирается,
идентификатор чата остаётся, чтобы не искать его заново.

Токен читается прямо из окружения, а не передаётся аргументом: аргументы процесса видны
в `ps` любому пользователю системы всё время работы установщика.

## Что стоит знать

**Токен из API не возвращается.** `GET /api/notify` отдаёт только признак `token_set`;
в панели поле остаётся пустым с подсказкой «токен сохранён». Пустое поле при сохранении
означает «оставить прежний» — снять галочку, не потеряв токен, можно.

**Включить без токена или чата нельзя.** Такая настройка выглядит рабочей в интерфейсе
и молча ничего не шлёт.

**Токен лежит в БД в открытом виде** — иначе его нечем было бы предъявить телеграму.
Файл БД и его каталог создаются с правами `0600`/`0700`; там же лежат приватные ключи
пиров, так что новой категории секрета это не добавляет.

## Диагностика

| Что видно | Что чинить |
|---|---|
| `токен бота неверен или отозван` | токен отозван в @BotFather — выпустите заново |
| `токен бота неверен: телеграм не знает такого бота` | в токене опечатка |
| `бот заблокирован в этом чате или не добавлен в него` | добавьте бота в чат и дайте право писать |
| `чат не найден — проверьте идентификатор` | не тот `chat_id`, либо забыт минус у канала |
| `телеграм недоступен: проверьте сеть на сервере` | с сервера не открывается `api.telegram.org` |
