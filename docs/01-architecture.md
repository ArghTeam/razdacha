# Архитектура

## Общая схема

```
┌──────────────────────────────────────────────────────────────────┐
│  Браузер: SPA (Svelte + Tailwind)                                │
│  https://<домен> из интернета или https://10.8.0.1 из VPN        │
└────────────────────────┬─────────────────────────────────────────┘
                         │ HTTPS + WebSocket
┌────────────────────────▼─────────────────────────────────────────┐
│  nginx — :443 (TLS) и :80 (редирект, ACME)                       │
│  конфиг генерируется установщиком, ADR 0008                      │
└────────────────────────┬─────────────────────────────────────────┘
                         │ proxy_pass на 127.0.0.1:8080
┌────────────────────────▼─────────────────────────────────────────┐
│  razdachad — демон на Go, root, systemd                          │
│                                                                  │
│   ├─ store         SQLite: пиры, туннели, правила, настройки     │
│   ├─ wg            управление wg0 через netlink (wgctrl)         │
│   ├─ nft           правила через netlink (google/nftables)        │
│   ├─ singbox       генерация config.json + управление процессом  │
│   ├─ lists         загрузка и обновление .srs / plain-списков    │
│   ├─ clash         клиент Clash API sing-box: latency, селекторы │
│   ├─ diag          проверки состояния                            │
│   └─ api           REST + WS, встроенная SPA (go:embed)          │
└────────────────────────┬─────────────────────────────────────────┘
                         │ пишет config.json, systemctl reload
┌────────────────────────▼─────────────────────────────────────────┐
│  sing-box — отдельный процесс, systemd                           │
└──────────────────────────────────────────────────────────────────┘
```

Два процесса, не один. sing-box запускается как обычный systemd-сервис, razdachad
генерирует ему конфиг и перезагружает. Причина — изоляция сбоев: падение sing-box не
уносит UI, и наоборот. Podkop делает так же
([разбор](research/podkop-analysis.md#ядро-podkopfilesusrbinpodkop)).

## Поток трафика

### Проксируемый трафик

```
1. Клиент резолвит youtube.com          → DNS 10.8.0.1 (sing-box dns-in)
2. sing-box: домен в списке правила      → отдаёт FakeIP из 198.18.0.0/15
3. Клиент шлёт TCP на 198.18.x.x         → приходит на wg0
4. nft: iif wg0 + dst 198.18.0.0/15      → mark 0x00100000
5. ip rule fwmark 0x00100000             → таблица razdacha → local dev lo
6. nft chain proxy: tproxy to 127.0.0.1:1602
7. sing-box принимает соединение, по FakeIP восстанавливает домен,
   сопоставляет правилу, открывает исходящее соединение через туннель правила
```

### Прямой трафик

```
1. Клиент резолвит banki.ru             → DNS 10.8.0.1
2. Домена нет в списках                  → обычный ответ, реальный A-адрес
3. Клиент шлёт TCP на реальный IP        → приходит на wg0
4. nft: адрес не в 198.18/15 и не в podkop_subnets → метка не ставится
5. forward → masquerade на eth0 → интернет с IP сервера
```

**Ключевое следствие:** прямой трафик вообще не проходит через sing-box. Нет накладных
расходов, нет лишнего хопа, отказ sing-box не обрывает доступ в интернет — только
селективность. Это важное свойство надёжности.

### Маршрутизация по подсетям

Часть списков — не домены, а подсети (Cloudflare, Telegram, Discord). Для них FakeIP
не работает: клиент идёт на реальный IP. Поэтому подсети дублируются в nft-сет
`razdacha_subnets`, и правило маркировки срабатывает по совпадению с ним. Тот же приём,
что в Podkop.

## Компоненты демона

| Модуль | Ответственность | Внешние зависимости |
|---|---|---|
| `store` | SQLite, миграции схемы, ключи пиров | `modernc.org/sqlite` (без CGO) |
| `wg` | создание wg0, ключи, пиры, статистика хендшейков | `golang.zx2c4.com/wireguard/wgctrl` |
| `nft` | таблица, цепочки, сеты, атомарная перезаливка | `github.com/google/nftables` |
| `route` | `ip rule` + таблица маршрутизации | `github.com/vishvananda/netlink` |
| `singbox` | сборка `option.Options` → JSON, валидация, reload | `github.com/sagernet/sing-box/option` |
| `lists` | скачивание `.srs` и plain-списков, кэш, расписание | stdlib |
| `clash` | опрос Clash API sing-box: latency, выбор в селекторах | stdlib |
| `diag` | проверки, агрегированный статус | — |
| `api` | REST, WS, статика через `go:embed` | `net/http` |

Импорт `sing-box/option` вместо ручной сборки JSON — принципиальное решение: конфиг
собирается типизированными структурами, ошибки ловятся компилятором. Это устраняет
самую тяжёлую часть Podkop — 1508 строк конструирования JSON через `jq`
([ADR 0006](decisions/0006-go-daemon.md)).

## Модель привилегий

`razdachad` работает под root — нужны `CAP_NET_ADMIN` для netlink (wg, nft, маршруты).
Ограничения systemd-юнита компенсируют риск: `ProtectSystem=strict`,
`ReadWritePaths=/var/lib/razdacha /etc/razdacha`, `NoNewPrivileges=yes`,
`RestrictAddressFamilies=AF_INET AF_INET6 AF_NETLINK AF_UNIX`.

Панель доступна из интернета, поэтому аутентификация обязательна и живёт в демоне
([ADR 0009](decisions/0009-public-panel-access.md)): пароль хешем argon2id в БД, сессия
в cookie, блокировка адреса после серии неудач. Демон не стартует, пока пароль не задан;
установщик генерирует его и печатает один раз.

Слушает наружу не демон, а nginx ([ADR 0008](decisions/0008-nginx-before-panel.md)).
Сам `razdachad` привязан к `127.0.0.1:8080` и снаружи не виден вовсе, поэтому реальный
адрес клиента он узнаёт из заголовков nginx — и верит им только на запросах с loopback.

Сертификат по возможности настоящий (Let's Encrypt через certbot), при отсутствии
домена — самоподписанный; он лежит в `/etc/razdacha/tls/` (ключ `0600`, SAN = IP
`10.8.0.1`, срок 10 лет). Самоподписанный вариант — запасной: в интернете он приучает
проходить мимо предупреждения браузера, то есть мимо единственной защиты от подмены.

Проблема первого запуска решается установщиком: он создаёт первого пира, печатает его
конфиг QR-кодом в терминал и рядом — сгенерированный пароль панели.

## Порты и адреса

| Что | Адрес | Примечание |
|---|---|---|
| WireGuard-сервер | `0.0.0.0:51820/udp` | единственный порт наружу |
| Панель, HTTPS | `:443` | nginx; из VPN доступен и `10.8.0.1` |
| Панель, HTTP | `:80` | nginx, редирект на 443 и ACME-проверка |
| `razdachad` (UI + API) | `127.0.0.1:8080` | loopback, за nginx |
| DNS для клиентов | `10.8.0.1:53` | sing-box `dns-in` |
| tproxy | `127.0.0.1:1602` | локально |
| Clash API sing-box | `127.0.0.1:9090` | локально, проксируется через API демона |
| Пул клиентов | `10.8.0.0/24` | настраивается |

## Состояние на диске

```
/etc/razdacha/config.yaml        настройки (порт, пул, DNS, MTU)
/etc/razdacha/tls/cert.pem       самоподписанный сертификат панели
/etc/razdacha/tls/key.pem        приватный ключ, 0600
/etc/razdacha/nginx-default-disabled.json   отметка: дефолтный сайт Debian снят нами
/var/lib/razdacha/state.db       SQLite: пиры, туннели, правила
/var/lib/razdacha/lists/         кэш скачанных списков
/etc/sing-box/config.json        генерируется, править вручную бесполезно
/etc/nginx/sites-available/razdacha   генерируется, помечен заголовком-маркером
/etc/nginx/sites-enabled/razdacha     symlink на файл выше
/etc/sysctl.d/99-razdacha.conf        ip_forward и ip_nonlocal_bind
/etc/systemd/system/razdachad.service
```

Приватные ключи пиров хранятся в БД. Файл БД — `0600 root:root`. Это осознанный
компромисс: альтернатива (не хранить и показывать конфиг один раз) ломает сценарий
«переустановил телефон, скачал конфиг заново», ради которого продукт и делается.
